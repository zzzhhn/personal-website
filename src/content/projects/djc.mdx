## Product thesis

A convincing web DJ product cannot stop at recreating the faceplate of a controller. The controls must drive a real audio graph, imported tracks must survive a later session, keyboard input must feel performable, and the system must degrade honestly when browser capabilities differ from native DJ software.

DJC is my end-to-end exploration of that product problem. It brings the dual-deck workflow into the browser while treating audio timing, interaction fidelity, storage, performance, and WebKit compatibility as first-class constraints.

## What I owned

- **Controller product:** built switchable RX3- and FLX4-inspired layouts with decks, jogs, transport, cue/loop, performance pads, mixer channels, crossfader, Beat FX, waveforms, and persisted material skins.
- **Audio engine:** implemented deck playback, tempo control, beat synchronization, key lock, effects, master/phones buses, recording, backspin, and optional stem processing on the Web Audio API.
- **Library workflow:** added local import, IndexedDB persistence, BPM/key/energy/beat-grid analysis, demo banks, and explainable Mix Order suggestions.
- **Performance input:** designed positional keyboard controls, continuous fader/trim operation, SHIFT layers, remapping, macros, conflict detection, and a bilingual guidebook.

## Audio intelligence and performance fidelity

A Web Worker analyses peaks, frequency bands, BPM, musical key, energy, phrases, and beat grids without blocking the main interaction loop. Synchronization accounts for first-beat offset and supports phase correction rather than relying only on matching displayed BPM values.

Key Lock uses an AudioWorklet path with a granular fallback. Backspin models release velocity, stale-input decay, throw thresholds, bounded speed, and exponential slowdown before handing control back to normal playback. These details make the interface behave like an instrument rather than a collection of buttons.

## Engineering around browser constraints

Recording does not assume one universal codec. The master recorder queries `MediaRecorder.isTypeSupported` and selects an available WebM or MP4/AAC path at runtime. Output-device selection, latency hints, vibration, autoplay, and other browser-specific APIs are capability-guarded instead of treated as guaranteed.

The rendering system caches interaction geometry, transfers analysis buffers out of the main thread, redraws waveform and LED surfaces only when state changes, stops animation work while idle, and suspends audio activity when the document is hidden. Optional HQ stem separation is explicit opt-in because the Demucs model is large; it uses WebGPU or WASM with Cache Storage rather than hiding the download cost.

## Product decisions beyond the deck

Imported music is user data, so tracks and analysis metadata are persisted rather than silently reset during iteration. Mix Order recommendations explain transitions using BPM, key, and energy. Controller skins and keyboard maps preserve semantic controls while allowing personalization. Each of these decisions extends DJC from an interaction demo into a reusable creative workflow.

## Current scope

DJC is an actively maintained stable release backed by automated tests, but it remains browser software. Feature availability depends on runtime capabilities, and this portfolio does not claim native-driver latency, universal device support, or professional-club certification.

## 产品命题

一个可信的网页 DJ 产品不能止步于复刻控制器面板。控件必须驱动真实 Audio Graph，导入曲目需要跨会话保留，键盘输入必须具备演奏感，而当浏览器能力不同于原生 DJ 软件时，系统也应当诚实降级。

DJC 是我对这一产品问题的端到端探索。它把双 Deck 工作流带入浏览器，并将音频时序、交互拟真、数据存储、性能与 WebKit 兼容性视为一等约束。

## 我的核心职责

- **控制器产品：** 构建可切换的 RX3／FLX4 风格布局，覆盖 Deck、Jog、Transport、Cue／Loop、Performance Pad、Mixer Channel、Crossfader、Beat FX、Waveform 与可持久化材质皮肤。
- **音频引擎：** 基于 Web Audio API 实现 Deck Playback、Tempo、Beat Sync、Key Lock、效果器、Master／Phones Bus、录音、Backspin 与可选 Stem Processing。
- **曲库工作流：** 加入本地导入、IndexedDB 持久化、BPM／Key／Energy／Beat Grid 分析、Demo Bank 与可解释的 Mix Order 建议。
- **演奏输入：** 设计物理键位控制、连续 Fader／Trim、SHIFT Layer、按键重映射、Macro、冲突检测与双语 Guidebook。

## 音频智能与演奏拟真

Web Worker 在不阻塞主交互线程的前提下分析 Peak、频段、BPM、Musical Key、Energy、Phrase 与 Beat Grid。同步逻辑会考虑 First-beat Offset 并支持 Phase Correction，而不是仅让界面上的 BPM 数字相同。

Key Lock 提供 AudioWorklet 路径与 Granular Fallback。Backspin 综合释放速度、陈旧输入衰减、抛掷阈值、速度上限和指数减速，最后平顺交还正常播放。这些细节让界面更接近一件乐器，而不是一组按钮。

## 围绕浏览器约束做工程

录音链路不会假设所有浏览器都支持同一种 Codec。Master Recorder 通过 `MediaRecorder.isTypeSupported` 在运行时选择可用的 WebM 或 MP4／AAC 路径。输出设备、延迟提示、震动、Autoplay 等浏览器专属 API 均经过 Capability Guard，而非被视作必然存在。

渲染系统缓存交互几何，将分析 Buffer 转移出主线程，仅在状态变化时重绘 Waveform 与 LED，并在空闲时停止动画、页面隐藏时暂停音频活动。HQ Stem Separation 采用显式按需加载，因为 Demucs Model 体积较大；它通过 WebGPU 或 WASM 运行并使用 Cache Storage，不掩盖实际下载成本。

## Deck 之外的产品决策

导入音乐属于用户数据，因此曲目与分析元数据会持久化，而不是在版本迭代中被静默清空。Mix Order 会用 BPM、调性与能量解释转场建议。控制器皮肤与键盘映射允许个性化，同时保持控制语义不变。这些决策共同让 DJC 从交互 Demo 成为可重复使用的创作工作流。

## 当前边界

DJC 是持续维护、具备自动化测试支撑的稳定版本，但仍然属于浏览器软件。功能可用性取决于运行时能力，本页面不宣称具备原生驱动延迟、覆盖所有设备或达到专业 Club Certification。

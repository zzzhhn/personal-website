## Product thesis

The hard part of AI-assisted quant research is not generating more factor expressions. It is converting an ambiguous investment idea into a testable object while keeping research judgment, data lineage, and failure modes visible. Alpha Agent is my attempt to build that controlled path: the LLM proposes within a grammar, deterministic code validates the proposal, and only numerically executable factors advance to backtesting.

## What I owned

- **Research workflow design:** turned a read-heavy prototype into an interactive workstation spanning hypothesis translation, diagnostics, backtesting, factor review, stress testing, gates, signals, and research history.
- **Typed AI boundary:** defined `FactorSpec` as the contract between language-model output and quantitative infrastructure, with explicit hypothesis, expression, operator, lookback, universe, and justification fields.
- **Safe execution layer:** built an AST walker that blocks attribute access, imports, lambdas, keyword arguments, unknown operands, and undeclared operators. Expressions are dispatched through controlled numerical functions rather than `eval` or `exec`.
- **Research quality gates:** placed low-cost synthetic diagnostics before real-data backtests so malformed, constant, unstable, or excessively high-turnover proposals can be rejected early.

## From hypothesis to evidence

The current static grammar contains 66 allowed operators across arithmetic, logical, time-series, cross-sectional, and group transformations. After schema and AST validation, each proposal runs on a generated 20-ticker panel. The gate measures the latest 10 days of cross-sectional Spearman information coefficient and supplements it with factor variance, turnover, input-perturbation robustness, and day-to-day rank stability.

Factors that pass can move into a real-OHLCV backtest path with a cached 37-ticker US panel and top/bottom portfolio construction. This does not claim that a synthetic check proves alpha. Its job is narrower and operationally valuable: prevent invalid research artifacts from consuming more expensive data and compute.

## Reliability as a product feature

The API distinguishes malformed specifications, provider failures, backtest capacity limits, and internal diagnostic failures instead of collapsing them into a generic network error. Router-level health visibility catches partially loaded services, while the frontend preserves hypothesis history and blocks degenerate factors before launching the next stage. Together, these mechanisms make the research process auditable and recoverable rather than merely impressive in a demo.

## Current scope

Alpha Agent is an actively maintained research preview, not an autonomous trading system. It demonstrates a disciplined human-in-the-loop workflow for factor research; it does not present model output as investment advice or claim live trading performance.

## 产品命题

AI 辅助量化研究真正困难的，并不是生成更多因子表达式，而是把含混的投资想法转化为可检验对象，同时保留研究判断、数据链路与失败原因。Alpha Agent 因此选择了一条受控路径：LLM 只能在既定语法内提出候选，确定性代码负责校验，只有数值上可执行的因子才能进入回测。

## 我的核心职责

- **研究流程设计：** 将以信息展示为主的原型重构为交互式工作台，贯通假设翻译、诊断、回测、因子复核、压力测试、研究门控、信号与历史记录。
- **强类型 AI 边界：** 以 `FactorSpec` 连接语言模型与量化基础设施，显式约束假设、表达式、算子、回看窗口、股票池与研究依据。
- **安全执行层：** 构建 AST Walker，拦截属性访问、import、lambda、关键字参数、未知 Operand 与未声明算子，并通过受控数值函数完成分发，全程不依赖 `eval` 或 `exec`。
- **研究质量门控：** 在真实数据回测之前加入低成本合成诊断，提前识别语法失效、因子退化、排序不稳定与过高换手等问题。

## 从投资假设到研究证据

当前静态语法覆盖 66 个算子，横跨算术、逻辑、时间序列、横截面与分组变换。候选表达式通过 Schema 与 AST 校验后，会进入 20 只标的的合成面板，计算最近 10 日的横截面 Spearman IC，并同时检查因子方差、换手率、输入扰动鲁棒性与逐日排序稳定性。

通过门控的因子可继续进入真实 OHLCV 回测路径，使用缓存的 37 只美股面板构建多空组合。合成检查并不等于证明 Alpha 有效，它承担的是更克制也更重要的职责：在投入真实数据与计算资源之前，阻止无效研究对象继续流转。

## 把可靠性做成产品能力

API 会区分规格错误、模型服务异常、回测容量不足与诊断内部失败，而不是统一呈现为“网络错误”。逐路由健康检查用于发现服务仅部分加载的问题，前端则保留假设历史，并在发起下一阶段前拦截退化因子。这些机制让研究过程可审计、可恢复，而不只是停留在 Demo 层面的视觉冲击。

## 当前边界

Alpha Agent 是持续维护中的研究预览，而非自动交易系统。它展示的是一套严谨的 Human-in-the-loop 因子研究流程，不将模型输出包装为投资建议，也不宣称具备实盘收益。

## 3．四个精选提案

### A．Video Rebirth：折景片场

**想走进去的画面。** 海边片场里，一幅很小的拱桥照片挂在取景架上。玩家把它对准远处断开的栈道，照片里的小桥忽然伸进世界；侧面看过去，它却只是一块薄薄的舞台切片。后台还藏着能从另一角度接起的路。

**一轮行为链。** 推动取景架找对位置 → 用预制景片覆盖一处断口 → 亲自跑到刚生成的桥上，确认它真的承重 → 从后台拿到另一片楼梯，旋转后接上高台 → 最后站进构图，拉动场记铃，让整段布景连续运动一次。

**为什么再玩。** 同一景片放在不同方向，会接出不同近路；一张看着很漂亮的构图，走近后可能挡住下一段。惊喜来自换角度发现“原来它是这样接上的”，再把自己的一段动作跑顺。失误可以撤回最后一片，跌落回最近安全落点，不收走已发现的景片。

**经历为何成立。** [Video Rebirth 内容](../../../src/content/experiences/01-video-rebirth.md) 明确视频生成质量、指令遵循与语义一致性评测；[EvalForge](../../../src/content/projects/evalforge.mdx) 又涉及运动真实性、画面一致性与可复核证据。这里把“画面里的关系，继续运动后还成立吗”变成可亲自验证的空间。场景是作者构造的魔法规则，不冒充公司模型的真实失败样本；公司经历与独立项目入口仍分别说明。

**空间／资产与首轮。** 一座前台可取景、背面可绕行的小片场，三片自制场景切片、两处接点和一座高台即可，先让约两分钟的一次拼接与通过成立。只接受预制景片与少量合法摆位，不承诺任意照片转三维。成本主要是视觉边缘、可走几何、相机与碰撞的一致性；不需要下载或生成视频，也不先做持续第二视口。

**来源边界。** C 的 `puzzles-perspective-reality` 明确“调整视觉关系后亲自移动验证”。其案例指针为 [Superliminal](https://store.steampowered.com/app/1049410/) 与 [Viewfinder](https://store.steampowered.com/app/1382070/)；本轮没有复制它们的图像、关卡、实现或任意几何转换能力。此案从旧片场候选收敛到一个明确可玩规则，而非继续加摄影棚装饰。

### B．字节 AIME：双塔换位赛

**想走进去的画面。** 两座相对的小塔之间，有一座会翻面的桥。你在高处看得到桥背面的标记，却够不到开关；搭档能拉动桥，但看不到它的另一面。过桥以后，两个人的位置和能看见的信息交换了。

**一轮行为链。** 爬到观测窗找出下一块落脚面的形状 → 向搭档指出目标并用铃声确认 → 搭档移动支撑，玩家踏上桥身 → 从侧面发现还需保留一块让搭档跟上的踏板 → 回身替它开路，一起抵达另一座塔，再交换主导者。

**为什么再玩。** 同一段桥可以先保人走近路，也可以先把搭档送到另一端再接应。反馈是桥的运动、伙伴探头与真实落脚，不是回答分数。误会时桥停在安全位置，搭档会指向不清楚的目标；玩家换个观察角度重新示意，不用整局重跑。首版不靠随机听错制造难度。

**经历为何成立。** [字节 AIME 内容](../../../src/content/experiences/02-bytedance.md) 包含用户意图、复杂指令、Human-in-the-loop 校准与失败恢复。双塔让“对象指得是否清楚、条件是否遗漏、结果有没有对上目标”影响真实行动；这比在终端里给一条回答打标签更适合玩。NPC 是公开规则下的角色，不宣称接入 AIME，也不搬内部用户请求或评测题。

**空间／资产与首轮。** 两个平台、一座受控转桥、一只搭档和两个有形状区别的目标，先做一次互相接应即可。玩家不看另一人的“答案屏”，关键线索就在场内，提示可用手势加短字幕。首轮单人加脚本搭档，不要求联网或自由语言模型。成本主要在看向／示意／等待的可读动作、桥的安全停靠与角色接触；规则数量保持少量。

**来源边界。** 使用 C 的信息分离与能力互补，改造为单人场景。目录案例指针包括 [We Were Here](https://store.steampowered.com/app/582500/) 与 [Trine 2](https://store.steampowered.com/app/35720/)；NPC、转桥和换位流程是本项目提案，不称为这两款游戏的原有单人实现。

### C．比邻：记忆绳伴

**想走进去的画面。** 一片高低错落的花架间，你和小搭档用一条绳相连。它蹲稳在你曾标记的平台上，你借绳荡到对面；等你站住，又轮到你把它拉过来。回头看时，两个人已经把一条原先过不去的路走通了。

**一轮行为链。** 在地面一起认识一个支撑点，亲手留下结标 → 搭档守住它，玩家借力跨过一处浅沟 → 玩家站稳后接应搭档 → 到岔路明确选一条路，搭档保留刚才认识的支撑点 → 若改变主意，亲手撤掉结标，它随之改用新点位，再继续另一条路线。

**为什么再玩。** 可以换谁先走、从哪个平台发力、何时让伙伴移动；一次轻轻收绳也许会把对方送上一个从地面看不到的花台。失误沿绳一起晃下来，会有可读的身体反馈，落到低处就从最近支撑点再试。探索到的点保留，错误选择可以改，不让伙伴替玩家预先知道整座花园。

**项目为何成立，以及哪里还要警惕。** [比邻内容](../../../src/content/projects/kindred.mdx) 的具体特点是持续上下文、显式证据、可追溯来源与可修订关系。因此搭档只能使用玩家实际标过、尚未撤销的信息，修改后也不能回到旧版本；帮助来自此前共同经历，不能只是“绳子象征联系”。它是作品主题的空间改编，不声称原项目有导航机器人，也不读取真实对话或上传简历。项目当前为归档原型，游戏角色不依赖其在线服务。

**空间／资产与首轮。** 一只低平台、一只高平台、两个有明显支撑姿态的角色、一条有界绳和一处可撤结标，先完成一次交换支撑。第一轮不加入全三维绕绳、联网和长悬崖。成本最高的是身体借力、绳长限制、支撑与镜头的一致性；不能把角色突然吸到落点当完成。

**来源边界与保留意见。** 主要来自 C 的 `cooperation-physical-tether`，案例指针为 [Bread & Fred](https://store.steampowered.com/app/1607680/) 与 [Chained Together](https://store.steampowered.com/app/2567870/)。把双人配合改成单人与脚本搭档、再加入可追溯记忆，是本项目推断。如果去掉记忆和更正规则后玩法毫无变化，说明项目联系仍弱，应留作普通游乐，不硬挂比邻。这是四案中映射与动作成本都最需验证的一案。

### D．合拍：接歌群岛

**想走进去的画面。** Beach Club 外有几座缓缓转动的大唱盘，像散在海边的圆舞台。相邻舞台先用一小段音乐招呼你；你把下一张唱片送过去，歌曲在乐句边界衔接，一段踏板随之展开，让人走向下一盘。

**一轮行为链。** 走上第一盘听种子曲 → 从两段候选试听中选下一首，拿起对应唱片 → 听清提示，在一个宽松的回应窗口把唱片抛给接盘台 → 真实转场发生，踏板展开 → 走上下一盘继续选，最后坐在观景位听自己串出的短 Set。

**为什么再玩。** 同一首出发曲，接不同下一首会改变走向；可以串得平稳，也可以故意拉起能量。进阶时部分提示灯短暂熄灭，音乐和时间仍连续，玩家凭已建立的拍感接上那一下。没有接准就保留当前曲，唱片就近取回，下一乐句再来；不会掉命或失去整段作品。自由听歌路线始终能走，不要求擅长节奏游戏。

**项目为何成立。** [合拍内容](../../../src/content/projects/hepai.mdx) 已明确下一首的兼容性排序、BPM／调性／能量、播放序列与 Cue-aware 双 Deck 转场。这里选的唱片必须实际改变下一首和衔接，而不是只让地板换色。**DJC 仍负责 Club 的操控与蹦迪体验；合拍的辨识点是选谁接谁、为何听起来连贯。** 具体音频接口需后续核对真实项目代码，不能仅凭说明文案称已集成。

**空间／资产与首轮。** 两座唱盘台、一段可伸缩步道、一处接盘点、三段获准音频，先做一次试听选择、实际接歌与跨台。旋转仅是低速可读的舞台运动，不先做失衡冲浪或高难平台跳跃。曲库未审计或算法未复用时，应称作者预编曲，不写成实时推荐；不能用随机 BPM、契合度或假转场填补。

**主要成本。** 音频时钟、输入反馈、预载和音量衔接优先于额外灯光。先只开一个场所音频所有者，限制试听并发；不加载整库分析、Stem 模型或持续大反射。隐藏／暂停时休眠。静音模式保留节拍视觉与普通通路，隐藏提示为自选难度；音乐的美感仍需听音验收，不能由拍点测试代替。

**来源边界。** 采用 C 的 `rhythm-cue-response`，将提示回应变成真实选歌接歌；`rhythm-hidden-beats` 只作可选进阶。目录案例指针为 [Rhythm Heaven Megamix 官方页](https://www.nintendo.com/en-gb/Games/Nintendo-3DS-games/Rhythm-Paradise-Megamix-1091313.html)；唱盘岛、步道和选曲组合是原创提案。此案替代旧“开车同时选歌”的负担，不把严格节奏判定叠到驾驶上。

## 4．优先级和首轮该看见什么

| 顺序 | 建议 | 先验证的体验，不是开发任务清单 |
| --- | --- | --- |
| 1 | 折景片场 | 玩家主动换角度、放一片景，然后迫不及待跑上去；侧面几何与可走空间一致 |
| 2 | 接歌群岛 | 下一首确实换了，耳朵听得到衔接，身体有路可走；接错也愿意再试一乐句 |
| 3 | 双塔换位赛 | 双方的观察与帮助都有必要，第二次会自发改分工；不是重复等 NPC 播动作 |
| 4 | 记忆绳伴 | 牵连的重量先好玩，记忆与更正也确实改变行动；否则撤回项目映射 |

**好玩先于讲解。** 每处用一个清楚的因果关系开场，解释留在自愿打开的项目入口。共用现有视觉气质，让灯、绳、景片、唱盘具有可信尺度与材质；不靠四块同款科技屏区分场所。这里不绘制全岛落点、不锁模型规格或开发 prompt，也不要求四处一起施工。

**必要的辅助与恢复。** 取景可稳定镜头，配合可暂候，落空可恢复，节拍挑战可减弱；重要区别同时用形状／动作表达，不能只用颜色或声音。提示和来源延续现有双语与返回逻辑。时长、人数、设备性能与趣味性均待小样实测，尚无相关通过结论。

**资源与权限。** 本轮预检为内存警告、可用盘约 10.11 GiB，因此全程只读文本／JSON、在内存解析；没有新增浏览器实例、运行世界、构建、生图、媒体下载或本地模型。后续样板应复用既有资源生命周期，静止／暂停／离场不留下无用更新。所有原作案例只用于机制研究，不复制代码、美术、音乐、人物或关卡；不引入公司私有评测样本、访谈内容或账户。

# 列车精修的局部性能验收

2026-11-04，审阅构建 `astra-car-perf-v8`，实际本机 Chrome。仅局部候选，4341 未替换。

## 结论

保留用户认可的近景原始 GLB，三节车厢按 8 种材质实例化；50m 外切换 5,221 面远景模型，44m 内切回，沿用原纹理和材质。三个车厢共用一套简化投影轮廓，停靠时不重复上传变换。原列车运动根、乘坐状态和物理保持不变。

同机位近景的全场渲染提交从原始精修 191 次降至 153 次，旧低模版为 149 次。远景从 298 次降至 261 次。近景高模 SHA256 仍为 `4f6e00d708b204a21091df701ad982ad77d75d809ce691137c27d90b53b2a9b9`，不是降低近景分辨率或改光源获得的结果。

原始记录为 `performance-v8.json`。`performance-v6-initial.json`、`performance-v7.json` 是诊断过程，分别包含重复投影和简化投影改动前的数据，不参与最终平均或最终通过结论。

## 运行验证

- 通过正常 UI 打开宝箱、取钥匙、开门、登乘。六题前置状态与站点定位使用明确的 QA 按钮，不冒充完成题目的人类试玩。
- 114 秒完整行程结束后，`ride-complete.json` 记录角色回站下车、乘坐状态清空、恢复登乘提示。实际截图抽查上车、翻滚中的车厢和下车；未做逐帧视频或所有接触面的穷举检查。
- 行程在 110.7219 秒暂停时，两次读取的渲染帧编号均为 19305、行程时间不变。`pause-proof.json` 同时确认暂停菜单可见。渲染读回停留在上一帧，不能用其旧 `paused:false` 字段否定实时菜单状态。
- 本轮控制台读取没有 error。回站后清除的只是 4353 验收页模拟任务进度，未动 4341。
- 近景、远景 GLB 验证及 14 项已有列车运动/接触测试通过。既有接触测试验证原物理和运动约束，不等于对新 GLB 所有细面逐一验证。

## 资源与生命周期

近景 21,772 面、8 材质、3 张 512px 图保持不变。远景 5,221 面、272,172 字节、无图像副本。借用 GLTF 几何、图像和渲染器环境缓存，只释放自有材质、实例缓冲与合并投影几何。视角和区域变化带来的全场纹理数量增加不能单独判作泄漏；本轮没有做长时堆快照或整世界内存证明。

代码、GLB 与审阅入口留在独立分支；生产入口未挂载。正式集成时保留这组固定条件进行回归，不能把本轮数字泛化为所有设备的预算。

# v37：吊运钢卷时保留标牌图集

本轮从 v35 实机记录的 `ibd-signs` 61 ms 工作块继续排查。原组件把语言和 `moved` 都作为整个资源构建的依赖：只搬动前卷标牌，也会重画 1024×1024 图集、重建几何及材质、上传新纹理。已拆成按语言构建的静态图案与按货物位置更新的顶点。

## 变化

- 前卷落稳或重开批次时，只改变对应标牌的四个顶点，并更新包围球。无效重复位置不触发 GPU 属性更新。
- 保留同一份图集、材质、几何、UV、法线及索引；仍是 25 块牌、50 个三角面、一个绘制批次，没有增加资源或后台任务。
- 切换中英文才重画文字，并在显示前应用当前货物位置。退出设施释放原来的三类资源。
- 文字、颜色、字形、尺寸、布置和操作规则均未重新设计，因此本次是保留既有视觉方向的性能修正。

## 验证

8 项定向测试通过：四顶点准确位移、其它牌不变、重复状态不重画／不上传、20 次移动与复位无累积误差、包围球覆盖全部顶点、中英标签完整、卸载释放，以及原吊架输入与接触门控。组件 strict TypeScript、Club 资产检查及生产构建通过，构建耗时 6.85 秒。

真实 Chrome、1710×875、balanced、晴天正午，复用同一个标签：

1. 正常领取货单，步行拿取工具，到吊架依次按住 ↑、←、↓。货物落稳后 `moved=['coil-front']`，动作和 pending 清空。
2. 回接货台重做本批，标牌复位。重新拿工具并完成第二次吊运。一次验收中途过早定位离开工具台，正常触发「走远，尚未记录」保护；返回后完成领取再操作，未绕过前置条件。
3. 第一段 71.197 秒采样包含阴影构建，工作日志达到 64 条容量上限，不能以其中缺少某事件证明没有重建。另开两个短窗口：复位 1.4003 秒／84 帧、落稳 3.6831 秒／221 帧，各仅有 `ibd-guide-cue` 和 `ibd-sign-position` 两个事件，未重建 `ibd-signs`。位置更新的两次时钟读数相同，低于本次计时精度，不声称真实零成本。
4. 搬运后切换 English，再恢复中文，标牌可读且前卷位置保持。两张实际截图均已查看：[中文](qa-20261029/ibd-signs-v37/landed-zh.png)、[英文](qa-20261029/ibd-signs-v37/landed-en.png)。浏览器 error 日志为空。

[完整运行记录](qa-20261029/ibd-signs-v37/runtime.json)。首段最后 1800 帧 p50 16.7 ms、p95 18.3 ms，全窗口最大 55.8 ms，仍有慢帧。落稳短窗口最大 27.5 ms。这些是局部观察，不能与 v35 不同昼夜条件直接换算提速倍数，也不代表全图稳定帧率、CPU／GPU功耗或所有设备。

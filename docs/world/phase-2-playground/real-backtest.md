# 因子矿石怎样落到真实回测

这是第一轮接入边界及后续修订，不是已完成的 API 设计。当前产品范围见 [PRD](PRD-alpha-factor-mine.md)，协作见 [开发计划](development-plan.md)。主线已读代码审计并选定三白名单，在 `4341` 先做本地真实历史重放；数据、结果和 manifest 留在 gitignored 本地，公开展示权待确认，本地体验开发继续。

本设计线没有访问真实行情、启动计算或验证外部服务。早期玩法画面保留在 [讨论稿](README.md)。

## 先把三种“真实”分清楚

| 结果模式 | 玩家实际看到什么 | 需要准备什么 |
| --- | --- | --- |
| 真实历史结果重放 | 一次已经完成、可追溯计算的曲线，明确标注“历史结果重放”、数据区间和计算时间 | 本地可追溯结果包、对应因子与配置、来源和版本；公开前另确认派生输出展示权；声称可复现还需有可用数据与运行环境 |
| 固定历史数据重新计算 | 对玩家这块矿石，在同一份真实历史快照上新算一次，明确标注“固定历史数据重算” | 可合法使用的数据快照、确定性回测器、可复现环境与计算资源；结果不是实时行情 |
| 联网回测 | 服务接受当前因子与配置后返回新的运行结果，展示实际数据截至日 | 上述数据和计算能力，加上经过验证的服务、身份边界、任务队列和故障处理；联网也不等于实时行情 |

**首版已选三白名单的本地真实历史重放。** 先用已有 Python kernel 跑出对应真实结果，再由设施重放；不依赖访客等待现场计算。它只能重放对应配置，不能假装支持任意组合，修改窗口后仍返回旧结果。现场重算与联网任务保留为适配方向，不是当前首版承诺。

没有任何合格结果包时，保留找矿、开采和投石的玩法草案，回测位置写明“暂无可展示的真实结果”。不以随机数、旧研究桌曲线、合成面板诊断或演出动画补位。

## 矿石必须有可追踪的身份

下面保留早期表达方式示意，不是当前矿石登记。当前三白名单已收敛为 `REVERSAL_5`、`ROC20_RANK`、`LOW_STD_20`，其精确表达式见最新 PRD；成交量矿示意不进入本 pilot。

| 矿石意象 | 对应研究对象 | 不允许暗示 |
| --- | --- | --- |
| 沿一个方向延伸的层纹 | 例如过去 20 个交易日价格变化的动量候选 | 顺着纹理挖就能预测未来上涨 |
| 折返的短纹 | 例如过去 5 个交易日价格变化取反的短期反转候选 | 反转天然有效或结果一定与动量相反 |
| 密集颗粒 | 例如当日成交量相对过去窗口均量的变化候选 | 颗粒更多就代表收益更好 |

矿石身份应引用一份固定登记：`factor_id`、版本、可读公式、引擎可执行表达式、允许字段、回看窗口、信号方向和适用数据。投池请求使用登记身份及获准参数，服务端重新校验。具体式子需由实际引擎适配并测试；本文不发明一个已经可执行的 `FactorSpec`。

若以后加入合成：只允许少量有定义的组合规则。组合会生成新的表达式和身份，需要新回测或完全对应的历史包。换一块皮肤不改变因子；改变公式、参数、股票池或区间就不能复用不匹配的结果。

矿点位置、石块纹理和碎屑可以有随机变化；研究结果必须由数据、公式和完整配置决定。矿更深、镐子更贵、操作更精准，都不直接增加回测收益。工具技巧影响找到和拿到什么，不给曲线加成。

## 真实计算至少依赖这些东西

1. **数据与公开权限。** 明确数据提供者、下载或生成时间、实际截至日、标的范围与时间区间；核对原始数据和派生结果的公开展示权限。快照保留复权、分红、退市与缺失值处理说明。若使用固定存续股票池，公开说明幸存者偏差和覆盖局限。
2. **计算定义。** 信号何时可知、何时交易、持有期、再平衡、组合权重、多空方向、基准及交易成本均明确。研究实现只能使用当时可得数据，避免把未来信息放进因子。不能把 IC 诊断直接称为策略净值。
3. **可复现输出。** 保存因子、数据快照和引擎版本，以及完整配置、运行标识、生成时间、曲线、有效样本范围和警告。哈希帮助核对一致性，不能单独证明数据真实或方法正确。
4. **服务与容量。** 若联网，由服务器持有数据／模型凭据；公开访客只提交受限的因子身份和参数。校验参数、限制并发与重复请求、返回任务状态，并避免公开入口转成无限制研究作业。缓存键包含所有影响结果的版本与配置。
5. **验证。** 用可手算的简短样本核对信号滞后、成本和收益，用相同快照复现同一结果；与独立计算核对曲线与统计。必须包含亏损、缺失数据、拒绝、超时与服务不可用的路径，不能只挑漂亮结果。

探索不同参数和区间会带来反复试验的选择偏差。若以后声称样本外表现，需要预先固定验证区间与规则，不能在玩家挖完后挑最好的历史片段。当前玩法不据此宣称发现可交易 Alpha，也不按收益高低决定是否允许继续探索。

## 池水怎样既有魔法，又不改写证据

投石那一刻，水花、低频和石头下沉可以马上发生。它们表达投掷动作，不表达因子好坏。

有合格结果后，池底时间轴上升起一条真实净值路径，亏损段同样保留。水光可以沿线流动，曲线数值、顺序、起点和尺度必须来自对应结果；比较时用同一时间、同一坐标口径，不逐条自动放大到一样好看。复杂的百分比、回撤和方法说明放在玩家自愿展开的详情里。

首版本地重放不把读包称为“正在回测”，也不显示虚构队列或计算百分比。数据和结果不入 Git 还不够，公开构建也必须排除这些本地文件；不将原始面板放进网站静态资源目录。

来源模式、数据区间和截至日放在结果旁，不能藏到项目外链。历史重放同时写明原计算时间；现场重算写明本次运行时间。仅用颜色不能区分盈亏或状态。

| 当时状态 | 场景里的反馈 | 可继续做什么 |
| --- | --- | --- |
| 排队／计算中 | 池边浮标显示文字状态和任务身份；只有服务确有总进度才显示百分比 | 把矿石留在托盘，继续探索，结果回来后亮一盏常亮灯 |
| 成功 | 展开本次对应的曲线和来源铭牌 | 对照另一块矿石，或自愿看公式和方法 |
| 数据不适用／候选被拒绝 | 铭牌说明是哪项数据或规则不满足，不把拒绝画成负收益 | 拿回矿石，换一个受支持的配置 |
| 超时／容量满／服务不可用 | 显示实际失败或排队状态；若仍在运行，先查任务，避免重复提交 | 继续玩或稍后重试；若可看历史包，明确由玩家切换模式 |
| 无真实结果可用 | 不画曲线，保留“暂无可展示的真实结果” | 继续找矿，直接访问项目介绍 |

## 美术方向与已有管线

- 保留岛屿的低多边形轮廓、石木暖灰色系和克制的科技青。矿场有明确的岩层断面、采掘痕迹、木结构承托和旧金属工具；磨损集中在接触、承重和高频使用位置。
- 岩壁先做连续的大体积与地层走向，再在局部安排断口和矿脉。不使用均匀锥体石堆、等间距晶体、无结构的随机三角噪声或覆盖整洞的发光面。
- 木料显示厚度、端面和连接；金属区分涂层、裸露磨损与氧化。矿脉以嵌在基岩里的细线和局部矿物面识别，亮度不暗示因子收益、稀有度或优劣。
- 已审阅 `tools/world/park/parklib.py` 的几何／导出／回读流程、`tools/world/camp-content/cc_lib.py` 的按材质类合批及顶点色、`tools/world/entry/build_portal.py` 的原生／重开／独立 GLB QA。复用几何和验证思路，在自有目录配置输出路径；不直接调用会写旧绝对路径的导出或渲染函数，也不改变这些共享库。
- 现有库的正面方向不同：park 为 Blender -Y，camp-content 为 +X。新批次统一记录为米制、Blender Z-up／+X 正面；只由 GLB 导出器转换一次 Y-up，禁止为了看图再补旋转。
- 使用现有 Blender 及实际导出器 RNA。上轮本机 5.1.2 的受控命令为 `--background --factory-startup --disable-autoexec --threads 2`；本轮仍先预检并等锁，不把上轮成功当成本轮运行结果。

## 分批资产

以下 ID、拆分与数量是制作建议，参考图和 PRD 对齐后再落尺寸，未冻结空间方案。

| 批次／建议 ID | 资产与作用 | 连接及运行时建议 |
| --- | --- | --- |
| 1／AM01 | 分层矿场主体：可辨认的入口、上中下层、岩层断面、采掘面与视线开口 | 岩壁和可走地面分别分组；矿体保留真实空腔，不用一个实心凸包包围矿场 |
| 1／AM02 | 连贯的下行与回望路线：岩台、木栈道、短楼梯或缓坡、必要护栏 | 接口共用边界／标高；地面、墙、护栏分组，连续接缝不留重叠台阶 |
| 1／AM03 | 入口与主轮廓木构：工具交接位置、承托门架、局部支架或旧提升结构 | 每个支架有可核对的硬结构承托和着地点；不靠帆布或悬空附件承担连接 |
| 1／AM04 | 回测池的实体外壳：石砌池体、池沿、接近与投放位置 | 保留真实敞口与池内体积；水面、结果、时间轴展示由主线接入 |
| 2／AM05 | 手持探测器：有重量的风化金属壳、手柄、探头与可读机械指示 | 独立握点、探头、指针转轴；显示真实检测状态，不把仪表刻度做成收益承诺 |
| 2／AM06 | 镐子：有弧度的木柄、可信厚度和磨损的金属镐头 | 柄头接合真实；提供握点与击打点，不修改角色骨架或动作 |
| 2／AM07 | 可开采矿脉及开采后状态：基岩、局部露头、断裂面、可脱落矿石 | 矿脉根部埋入指定基岩；待采／破开／空槽使用一致接口，避免整面岩壁突然消失 |
| 2／AM08 | 可携带和投放的矿石、少量命中碎屑 | 体积和重心适合拿取；固定矿石身份与外观映射由 PRD 决定，碎屑不伪装成新因子 |
| 3／AM09 | 仅补确有作用的细节：矿车／料筐、绳缆、旧轨或管线、灯具、工具搁架与少量碎石 | 根据最终路线选取，先证明功能和连接位置，再制作；不堆满走道或遮住交互点 |

第一批应在不依赖道具和 UI 的情况下读出完整设施：看得出从哪里进入、怎样下到矿脉、如何回到池边，远景也有一眼可认的轮廓。先交一个协调的空间样板供主线整合，不先批量生成一套孤立石块。

第二批让探测、敲击、拾取和投放各有一个清楚的英雄对象。候选矿纹可以用层纹、折返纹、颗粒区分身份，但具体数量、公式与颜色映射以主线登记为准。

## 尺寸、节点与碰撞接口

- 参考人物尺度为 1.7 m。路线净宽、净高及工具长度在 PRD 对齐时列出实值；现有角色地面支撑上限为 25°，视觉缓坡／阶梯与主线行走支撑面必须对应，不靠过陡的隐藏坡面补救。
- 单体道具采用底面中心根节点，并提供握点等子节点。多层矿场优先讨论以入口平台为设施基准，坑底可以是负标高；不能一边按入口摆放，一边又把整座矿场任意底部归零。最终约定写入 manifest。
- 根节点带稳定资产 ID、米制尺寸和版本。建议使用 `surface_*`、`wall_*`、`rail_*`、`vein_*`、`ore_*` 分组；需要动作的部件保留独立节点和转轴，不为减少对象数焊死。
- 道具接口候选为 `socket_grip_R`、`socket_probe_tip`、`socket_impact`、`socket_ore_release`；池体提供 `socket_drop`。输出最终 GLB 坐标，主线按节点接入，不从包围盒中心猜握点或投放点。
- 矿场静态支撑面建议来自同源简化网格，岩壁／护栏单独给硬碰撞；可携带矿石与碎屑使用适合的小凸体。池体碰撞保留敞口，不以一个整盒覆盖空腔。模型文件与碰撞建议只描述资产，不自行写运行时注册。
- 为相邻模块输出可测的边界点、台面标高和插接位置。单独记录有意埋接；可拆部件检查接近、拿起和退出空间，不能只检查最终摆放姿态。

## 预算与装载建议

现有预算工具按真实 main／sun／fire pass 计数；历史文档使用约 300 calls／500k 三角的全景规划线，历史视角曾经超限。它们不是本设施已有的预算余量，也不是当前 pilot 的性能实测。

首批先以整体近景约 20–35k 三角、远景轮廓约 3–6k、简化静态阴影代理约 2–4k 为工作量估计；第二批英雄道具与矿脉合计约 10–18k，第三批按最终空缺再分配。以上不是压制造型的硬封顶：参考需要更多几何时，说明实际轮廓收益、最终计数和可选 LOD，再由主线结合整岛实测判断。

优先按石、木、金属、矿物等语义分少量稳定材质，颜色层次可用顶点色；不同物性的粗糙度不能只为合批而抹平。先不增加图片贴图和灯；矿物只作局部适量光泽，发光值需在日／夜实景中确认。预览灯、相机和地板不得进入 GLB。阴影代理不能堵住入口或替代近景岩壁轮廓。

源文件按批次保存，GLB 按运行时需要的模块拆分，加载范围由主线设施边界决定；避免远处访客先加载整座地下空间和全部英雄道具。最终提供每个文件的字节数、实际三角面、材质槽和节点清单，由主线测完整画面成本。

## 每批交付和质量验收

1. **视觉先看体积。** 对照主线参考做一组相同光照的整体、入口视角和玩家高度近景；首批必须读出分层、路线、矿壁与池体，不能靠贴图或面板补足空间。黑白／clay 图检查轮廓、厚度、承托和接触；再看彩色日／夜材质。实际图片需读取检查，不把成功渲染当成审美通过。
2. **材质分工清楚。** 石面是岩层和断口，木件有厚度及端面，金属有与用途一致的磨损；矿脉嵌在基岩里，关闭发光后仍可辨认。避免塑料感、机械等距重复、悬浮装饰及细碎噪声。
3. **连接与空间可用。** 每个落地脚／支撑面留实际见证；检查指定插接、可走接缝、池口以及矿石的拿取／投放路径。固定部件、埋接部件与活动部件分开判断，不以 Join 代替连接，不把整个设施塞进一个凸包。
4. **几何与交换。** 运行 evaluated native 检查，保存后重开 BLEND，再独立导入确切 GLB；核对有限坐标、退化三角、绕序／闭壳、尺寸、单位、节点变换、实际三角数和完整材质记录。任何 Mesh.validate 会修复的数据都先回到生成源处理。接缝分裂的原始统计和容差焊接诊断分别保留。
5. **可复现并可接入。** 每批提供 builder／QA／render 入口、可编辑 BLEND、GLB、manifest、哈希绑定的检查结果、少量本地图片，以及尺寸／材质／连接／碰撞建议。分开记录原生检查、GLB 交换、内部画面检查和主线真实运行验收；资产图中的人物尺度参照不算动作验收。

建议目录：`tools/world/alpha-mine/` 保存脚本、分批源文件和 QA／本地视觉证据；`public/world/alpha-mine/` 只放运行所需 GLB 与必要资源。详细文件名在第一批开始时记录，不把过去历史证据拷进新目录。

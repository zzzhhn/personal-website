## 独立运行时问题

原 `sweptPlayerVelocity` 在 Rapier character-controller 的 WASM 查询回调中调用 `owner.isDynamic()`。真实固定刚体参与的最小平地场景，执行一次后 `world.free()` 报 `attempted to take ownership of Rust value while it was borrowed`。相同场景不传 filter、filter 固定返回 true 或只读 JS userData 则可清理。原窄道夹具使用无父级 collider，未覆盖这个查询边界。此结论是查询／生命周期问题，不冒称已经证明它导致了西坡几何卡角。

修正先用局部 AABB 收集可能命中的 collider，在查询返回后读取刚体类型；正式 character query 只查 handle 集合。局部包络包含胶囊尺寸、完整步长和 2 厘米余量，涵盖滑动路径。候选数组和排除集合按 controller 复用，不做每帧全场刚体扫描。原过滤语义保持：固定体、无 parent 碰撞体、运动学体和车辆阻挡；动态松散道具留给原物理解算推动；传感器仍由原 flags 排除。

`player-query.test.mjs` 覆盖上述六类、20 次重复查询后销毁，以及远处刚体不被扫描。原角色运动、矿区静态检查与相机检查合计 **33/33 通过**；`player-motion.ts` TypeScript strict noEmit 通过。没有声称测过实际页面帧时间或长期资源表现。非零水平步行每步增加一次局部 broad-phase 查询。

## 保留的几何失败

局部低夹槽起点 `[-14.2,0,-5.6]` 可以容纳处于夹挤接触中的胶囊，却不能沿尝试的南／北路径离开：

- 南向目标 `[-14.2,0,-3.4]`，停在 `[-14.2925,-0.0014,-5.8974]`，313 步，移动仅 0.69 米。
- 北向目标 `[-14.2,0,-7.1]`，停在 `[-14.2883,-0.0016,-6.1854]`，233 步，移动仅 0.80 米。
- 头顶碰撞 witness 约 `[-14.27,1.636,-5.9]`，法线向下，来自 surface 类；西侧 solid 接触约 `[-14.6214,0.3175,-5.9914]`。这也说明“capsule 只检查 solid、地面只采向下 ray”的静态测试会漏掉低顶。
- 临近固定箱 `AM05_crates-315` 中心 `[-13,0.4275,-5.7]`、尺寸 `[0.95,0.855,0.95]`；坡端柱 `AM02_ramp-west-0-3_posts-2` 在 `[-13.08,0.46,-9]`。只移动箱子不能消除低顶和岩面夹槽。

主线已转交美术。美术拟将 raw 单元 x=(-14.6,-13.1)、z=(-9,-3) 的同一闭壳支座加厚到 2.7 米（warp 后最低高于 2.3 米），并将箱体移至 `[-3.8,0,-17]` 储料区。此范围覆盖上述失败点，正式西低出口 x≈-15.8 与核心坡 x≈-11.8 位于单元外；仍须用最终实际碰撞重验。要求保护至少 0.9～1.0 米有效净宽、1.9 米头顶净空，并考虑实际岩面 relief；此处不能保留可落入却不可站立的低腔。

新 `quarry-traversal.test.mjs` **在 3870aef 上为 10 通过、1 失败**。失败是有意保留的真实安全回归，不是 skip/TODO：旧低槽必须被真实 solid 封合，或至少有一条连续步行通路回入口，才会转绿。封合分支只声明旧位置已不可容纳胶囊，不把它叫作“从夹槽走出”。不用回营地按钮掩盖失败。

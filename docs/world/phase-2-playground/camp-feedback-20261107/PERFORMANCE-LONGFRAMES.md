## 阴影分块长帧

主协调后续的原版暖启动窗口报告 shadow job 608 slices、累计约 3,746 ms、最慢 slice 480.7 ms。同期 rescan 最大 12.3 ms、applySunPass 最大 18.7 ms，GPU 样本最大 29.14 ms。第二个 600 帧窗口至 1,238 slices 仍 pending，内存压力为 warning。两个窗口都未隔离到具体 generator 单元。原 phase 数组为空，正由主协调在同基线的诊断构建补采。两轮都不是稳定帧耗 A/B。

源码中 transform 每 1,024 顶点、bin 每 512 三角、buffer 每 4,096 元素、bounds 每 1,024 顶点让出。但旧 bin 往两份会随桶增长的大 JS 数组追加坐标和索引，扩容与 GC 的代价不受循环计数限制。候选 `f2d4d39cb1575145b13d41e72cf42d127af54b3d` 将桶改成定长 Float32 页，首 32 三角、后续每页 256 三角。最终仍按原顺序写成相同的连续位置和索引，索引直接按顺序生成，保留 Uint16/Uint32 边界。保留已发布缓存和原子发布规则。

对同一 90,000 重叠三角 × 3 级联的纯 Node 夹具，各运行一次。采样 heap 峰值 80.9 → 12.6 MiB，ArrayBuffer 峰值 13.0 → 20.4 MiB。两种峰值分别取样，不能相加视为 RSS。bin 最大单元 3.02 → 0.35 ms，bounds 最大单元 0.44 → 1.12 ms，均只描述这两次有界运行。夹具未复现浏览器 480 ms 长尾。22 项阴影测试通过，覆盖几何顺序、追加、索引宽度、取消、原子发布、实际 pass 选择和投影覆盖。最终连续缓冲分配、来源校验与整批发布仍可能产生单元长帧，按浏览器 phase 或 GC 证据再决定是否需要处理。

## 当前决定

- 用户认可过山车 v1 的视觉方向，原话：「‘过山车’的示意图的视觉方向没问题」。保留切面海岸世界、角色比例、灰白设备体量、蓝灰结构、青色技术灯和暖色公共空间照明。
- 用户认为装置难度、刺激度和复杂度不足，允许增大 1.5～2 倍。v2 按**相对参考图 v1 的占地约 1.8 倍**讨论，约 80×100 m 改为 110×130 m；不是已经测量完成的模型面积，也不是现有 70×84 m 实现的 1.8 倍。
- v2 主塔目标高度 40～45 m，替代现有约 30 m 量级。参考构图包含陡降、贴地段、驼峰、一次倒置、高位大弯、低位 S 弯、设备楼螺旋和灯廊回站。用户已批准继续实施；最终形体及乘坐体感由运行样板校准。
- 国投 v1 日景方向已批准，同构图夜景仅补照明参考。保持物资清点的工业体验，不混入过山车的霓虹主题。

## 乘坐体验校准

先做一条有实际座面与角色的轨道样板，再补全场精模。建议节奏：约 20～25 秒攀升，塔顶短停，首次陡降，贴地冲刺，驼峰释放，一次倒置，连续 S 弯，灯廊，制动回站。最初样板为 122 秒。用户于 2026-10-28 实测后要求首降后至少提速三倍，当前调整为 70 秒：前 36 秒离站、爬升、塔顶停顿不变；原 36～114 秒的刺激段压缩为 26 秒；末尾保留 8 秒制动。不为了扩大面积而拖长乘坐。

旧版 `coasterFrame` 使用前向与世界竖直轴叉乘，近垂直时会退化。本次改为连续运输的轨道坐标架和连续翻滚角；列车、座面、角色共享完整四元数。默认追尾可看见列车翻滚，舒适视角保持地平线并限制俯仰；第一人称的完整翻滚由玩家主动选择。不能只旋转镜头假装轨道翻滚。

## 实施门槛与交付证据

1. **参考确认：** 分别记录风格、布局的用户确认，只更新用户实际认可的范围。过山车 v2 与国投 v1 均已获准继续实施，无需重复询问。明确同一批准版本的日夜参考。
2. **空间与动作样板：** 先验闭合轨道、支撑与净空、落差节奏、角色座面、默认与舒适镜头、暂停／退出／回营地。国投先验高廊、吊运与车厢通路。不先铺满细节。
3. **代表性美术样板：** 过山车先完成入口＋车站＋一段高架；国投先完成钢卷棚＋高廊＋一段装车通路。白天看形体和材质，深夜看被照亮的面、路径与角色。
4. **扩展和对照：** 样板合格后扩展到全场。用锁定的引擎机位、FOV、画布尺寸、时间、天气、曝光及质量档采图；同一机位昼夜对照，不能用换角度、美化后期或隐藏 HUD 代替实际可玩画面。
5. **推广到 4341：** 视觉、玩法、物理与镜头、性能四栏分别留证。任一未验仍标未验；构建通过不等于视觉通过。用户已经授权的事项不重复请求授权。

所有大型视觉任务 brief 必须带本文件、对应 manifest 和明确资产版本。规则入口为 `src/components/world/AGENTS.md`。轻微修 bug 且不改已确认方向，无需重新走整套参考流程。

## 五项失败条件

1. 入口图缩小后只剩细轨和柱子，分不清站房、主塔、检修桥与灯廊。
2. 总览仍是三个桌子加一圈轨道，看不出前场、中层设备与高层回路，或扩建只是等比例拉大旧轨。
3. 夜间只见灯线，站台路面、塔体侧面、人物与车厢消失；不能用全局曝光升亮掩盖缺少局部照明。
4. 不看 HUD 无法辨别锁／箱盖／钥匙／门的状态，或装饰抢过交互焦点。
5. 乘坐中的桥、壳体、灯廊挡住角色和前路；倒置产生坐姿脱离、姿态突跳或舒适镜头随车翻满一圈。

## 性能和造型如何同时成立

夜间当前根因之一是 `MeshBasicMaterial` 灯线不会照亮其它物体。静态面光和接触阴影优先用烘焙／顶点夜间补光；若采用 lightmap，必须保留合批时的必要 UV。近处人物／列车只使用少量有界补光，最多两盏局部无阴影实时光作起点，不逐灯投影。

主体增加塔、机房、检修桥等轮廓和成组细节；重复支撑／轨枕实例化，远景保留大形。不把近景所有螺栓常显，不增加全屏高成本 bloom、实时倒影或常驻轮询。扩大布局后重新量测，不把上版混合状态帧窗当性能保证。资源紧张时串行构建与浏览器验证，保持同机位同质量比较。

## 设计复核

当前概念的主线保持：切面风格、三级轨道、具象设备、冷暖有主次的夜景。修正重点是轨道拓扑与实际净空、手部可达的装置细节、夜间人物补光。内部五维初审：风格一致性 8、视觉层级 8、细节执行 8、功能可落实性 7、辨识度 8；这是作者概念审查，不是用户视觉验收，也不是模型性能数据。

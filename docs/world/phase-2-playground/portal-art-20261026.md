## 门洞与门槛

原门内圆半径 1.25 m，圆心离基座 1.65 m，几何内径为 2.5 m，原下沿离地 0.4 m。保留这个圆形，增加宽 1.9 m、顶高 0.55 m、中央平段长 1 m 的石台；local Z 两侧各以 2 m 短坡过渡至坡脚，坡脚比原地面高 12 mm，覆盖公园石板最多 6 mm 的微起伏。坡度约 15.06°。

石台顶上，圆孔沿中线最高净高为 2.35 m，石台与圆交线净宽约 1.187 m。圆形不能等同为 2.5×2.5 m 的矩形通道。使用当前 `PLAYER_RADIUS=.34`、`PLAYER_HALF_HEIGHT=.48` 的直立胶囊，总高 1.64 m；在台面正常站立，加入 3 cm 的圆孔安全余量后，胶囊中心可用横向范围约 ±0.44 m。`portalCrossing` 把胶囊两端圆心各加半径及余量，检查是否都在真实内圆内，拒绝平地脚部穿石、过高跳跃与侧擦门框。

`createPortalThreshold` 的 16 个顶点、28 个三角形由视觉与 Rapier fixed trimesh 使用同一份数组。每站只有一个固定碰撞体，未给原石门框、光幕或粒子增加碰撞。`PORTAL_THRESHOLD` 集中定义尺寸，arrival 位于 local Z=±2.5 m 坡脚，QA approach 位于 ±3.2 m。

## 实际作者轴修正

主线浏览器侧视发现首轮圆环与光幕相差 90°。首轮只检查了圆径与胶囊配置，没有验证 GLB 的实际作者平面，这个遗漏已修正。真实 `G28.glb` 的根元数据为 `frontAxis=+X`，圆环位于作者 YZ 平面；光幕、门槛坡道及 crossing 合同使用 local XY 圆面与 +Z 法线。

`WorldEntry` 对 high／low 的圆环 mesh 统一施加 `PORTAL_FRAME_YAW=-π/2`，把作者 +X 正面转成 local +Z。变换发生在合批后的 mesh，保持圆形、几何批次、源 GLB 和节点不变；门槛、光幕以及主线 QA 中的 site position／yaw 没有改动。QA facts 增加 `sourceFrontAxis`、`frameYaw`、`localOpeningNormal`，便于主线读回。

使用本地 `draco3d` 解码当前实际 GLB 的全部 30 个 mesh、3,024 个顶点及 4,392 个三角形，并应用与运行时一致的层级矩阵与 mesh 旋转，验证通过：

- 原作者尺寸 `[0.9300157,3.3193192,3.3104197]`，修正后 portal-local 尺寸 `[3.3104197,3.3193192,0.9300157]`，最薄轴为 Z。
- 修正后顶点 XYZ 方差为 `[1.1825104,0.9070072,0.0682599]`，Z 方差分别小于 X／Y 的 15%，圆环主平面为 XY。
- 作者正面 `[1,0,0]` 经相同旋转变为 `[0,0,1]`，与实际光幕几何的 +Z 法线一致。
- 使用每个实际解码 mesh 的包围盒重建 low 包络并应用同样变换，其整体 min／max 与 high 实际顶点边界一致，误差小于 `1e-6` m。

这是实际资产几何验证；未在协作者端启动浏览器或 build，修正后画面仍由主线正在使用的浏览器统一复核。

## 设计原则复核

| 原则 | 当前具体决策 |
| --- | --- |
| 意图匹配 | `WorldEntry` 光幕贯穿圆洞，普通步行触发由主线连接 |
| 减少认知负荷 | 不增菜单、目的地列表或按键要求 |
| 状态可见 | 半透明孔面和低强度悬浮光屑标示入口 |
| 可恢复 | 两侧保留坡道与候选落点，安全传送／冷却由主线负责 |
| 可操作暗示 | 先有真实可走门槛，再以真实胶囊穿面判定 |
| 界面隐退 | 沿用场景原石环，不覆盖新的面板 |
| 无需手册 | 角色步行穿过光幕，QA 需验第一次可发现性 |
| 尊重时间 | 无附加载入、目标选择或等待动画 |
| 无误导 | 不把固定候选当成安全到达，运行时逐次探测 |
| 单一主操作 | 门的操作只为穿过，地图使用原右上入口 |

跨表面约定：未新增文案或字体，未改 i18n、布局包裹、侧栏导航或本地化数据。继承原昼夜色调与现有运动偏好时钟。

## 3．国投 IBD：综合物资盘点场

### 核心循环：把看不清的事实翻出来

**看见一个不确定处 → 选工具或换观察路径 → 吊、转、开、排出可见证据 → 用另一种办法核验 → 让正确的一批货真正通过发货口。** 数量和质量都是物件的状态；最后才在随身小货单上留一个确认标记，不把游戏做成连续填表。

| 场区 | 亲手做什么 | 意外与不同解法 |
| --- | --- | --- |
| 钢卷中庭 | 用可见的吊架提起遮住视线的前卷，转动承托台；拿手电沿卷边看凹痕、锈斑与标识 | 从地面看是一层，走巡检廊才发现后排；可以先上高处定位，也可逐步移开前排。瑕疵只在能看见的位置出现，不随机判坏 |
| 五金料棚 | 拉出浅托盘、揭开覆盖布，先把一批货放上台秤，再开箱、展开内托；把少量样件放入有轮廓槽的比对盘 | 秤提供需要进一步核实的线索。包装皮重、规格与混装都可能造成差异，不能仅凭重量断言数量或质量；开箱后可借槽位和内包装单位交叉确认 |
| 发货仓／月台 | 拉出货盘、打开车厢，在立体仓库沿货位与游戏运单号追货；按实际装载事件核对，再封车 | “已备货”和“已经装车”不是同一批；一大箱也可能含多件。可进车厢核对，也可沿装车轨道逐托确认；正确货物原样放行，有差异才换货 |

有记忆点的一刻：玩家把一卷钢卷吊开，之前以为的“墙”后面露出一整排货与通往五金棚的小通道。解决差异后，自己核过的一托沿滚轮进入车厢，月台门升起，能看到这次判断真正改变了什么。

**一轮约五分钟。** 0:00～0:40 看整车目标、拿手电和标记工具；0:40～2:00 选高廊或吊架核钢卷；2:00～3:10 开一个五金托盘，辨规格与包装单位；3:10～4:30 核装车与货单、换一托；4:30～5:00 看发货完成，发现另一条调查路径。目标时长不设倒计时，新手可以慢慢查。

**重玩理由。** 换遮挡、货架前后关系、规格与装载位置，保持证据自洽；玩家可以练更少搬动、更聪明的观察路线。既有“看似一致，核查才见差异”，也有“看似可疑，复核后完全合格”。**首轮至少准备一个完全合格和一个有明确差异的案例**，不要求每次、每区都挑出错误。差异由开局明确状态决定，同一局不会检查前后改答案。不做随机“审计通过率”、战斗、扣薪或职业排名。

**证据充分条件（仅指游戏验收）。** 钢卷须使目标货位及遮挡后物件可辨、核对唯一身份与规定外观面；五金须确认规格、包装层级和题目要求的计量单位，内件未显露就标“仍待核实”；发货须使运单要求与车厢内唯一货物、单位和已装事件对应。数量成立不自动代表质量成立。重量、标签、照片或看过某一个角度均不能单独替代全部条件；允许用不同工具／路线得到同等充分证据，再明确报告“一致”“有差异”或“信息不足”。

**首次可开发切片。** 一处有完成质量的钢卷吊点、一张可开合五金托盘、一个可进出的发货月台，串成一次核验与实际装车。总共只需几卷钢、少量样件与两托货，但三种操作都要成立；大型厂区在这个循环好玩后扩展。手电、吊钩接触、物件重量和钢／木／包装材质必须在普通相机中可信，占位箱堆不能定义完成。

| 最可能不好玩的三点 | 改法与观察标准 |
| --- | --- |
| 最后仍然只是站着报数 | 每区至少有一次改变视线或物件关系的操作；同一批货允许高处观察与吊开遮挡等不同路径；若不移动／不开物件也能全做完，重做场景 |
| 证据藏得太细，变成找像素 | 首例差异有明显轮廓、声音或包装层次提示；手电和高廊各有用途；不是靠极小文字或单一颜色判定 |
| 吊运和装车比盘点还烦 | 吊架用少量受控落点和清楚的托位，落空可就近归位；不先加入完整叉车驾驶、长搬运或散落上百零件 |

## 4．字节 AI PM：骤变回路／Sudden Shift

### 核心循环：看懂一个人的目的，亲手换来一次骤变

**在门外遇见有情境的请求 → 操作对应物件说明判断 → 看到短反馈并纠正 → 六个不同任务正确 → 开宝箱、拿钥匙、开大门 → 上车经历抬升、停顿与突然下坠。** 分类的紧凑判断与轨道的骤变节奏共同表达用户所说“突然”，不把过山车本身改成评测工作台。

**明确门槛。** 首版七个原创任务，累计六个不同任务正确，达到 `6/7` 即可开箱。每题只记一次正确，重复操作不能刷数。答错让装置短暂演示所选动作的后果，再回到原情境纠正，不扣已有正确数；需要澄清的题先问清再分类。任务、宝箱都在锁住的大门外，避免拿不到钥匙却进不了题区的死锁。

六道门槛锁打开后，玩家仍须亲手掀箱盖、取出实体钥匙、走到大门开锁。钥匙和开门状态保留，之后可以直接重坐；离开、重入或刷新也保留本机已获正确任务，不跨设备承诺同步，不上传作答。主动重开只清本设施进度，不影响矿区、交易所或 Club。

**分类如何有情境。** 七题共享三类小景：会动的路线／道岔、可翻转加工的文字物件、可追问的访客。玩家拨轨、排序、将原件放进合适装置、摇铃追问，随后看目的有没有被理解。意图名称用短标签辅助，不连续弹七张单选卡；同一张票可能要求查询，也可能要求提取，物件颜色或外观不能直接泄露答案。微动作展示的是分类判断，不再额外要求写代码或完成七份工作。

**大型轨道的记忆点。** 列车沿有实体支撑的抬升轨越过灯光门，先让人看清全岛；顶端停一瞬，前方轨道被塔身遮住，再突然落入低处反弯，穿过一段封闭灯廊，贴着岩面回到开阔处。刺激来自高度、速度反差、近景擦过与声音，不靠满屏闪烁、镜头乱抖或连续七次问答中断乘坐。

赛博朋克沿用现有 faceted／stylized 模型：粗细有层次的钢轨、哑光折面塔架、局部发光导线与少量灯门。黄昏也能辨认轨道；夜间增加轮廓光，不用写实城市贴图、全透明霓虹建筑或到处悬浮广告板。默认跟车视角，第一人称可选；提供低翻滚观景模式与随时回站，两种乘坐方式都需要先取得钥匙。

**一轮约五分钟。** 0:00～0:25 看锁门、宝箱与高轨；0:25～2:40 在三个小景内完成六个不同任务，可选第七题，允许纠错；2:40～3:10 开箱取钥匙开门；3:10～4:45 完整乘坐；余下时间下车看静态构图或再坐，不要求视频录制。七题单次判断与反馈尽量短，不设强制排队或演出等待；约五分钟是目标，不是必须按秒通关。

**首次可开发切片。** 七题全部保留，用两三类高质量交互物件复用，跑通六个 unique 正确、开箱、拿钥匙、开门、上车与回站。轨道先做一段有完整支撑、抬升、停顿、骤降和返回的短环，约 45～60 秒，用来验证乘坐张力与恢复；它是垂直切片，不冒称已经完成大型全园。大版再扩展到约 90～110 秒及反弯／灯廊，不先堆满闲置设施。

| 最可能不好玩的三点 | 改法与观察标准 |
| --- | --- |
| 宝箱前仍是枯燥刷题 | 三类小景交错、原话与对象共同构成判断，正确后有实际物件回应；每题约十几秒即可开始操作，避免长讲解或强制等待 |
| 题目模糊，却被唯一标签乱判错 | 用下一节自创口径，按最终目标判主意图；合理别名可接受，信息不足允许澄清；错题指出缺了什么，不扣已得进度 |
| 宣称刺激，实际只有匀速绕圈，或晃得难受 | 首轮就做出抬升、可预期的安全停顿、突然下坠和开阔回景；先检查速度曲线、支撑与镜头；低翻滚与回站可随时使用，不以眩晕当完成指标 |

## 5．七个自创意图情境

本设施自定六类主意图：查询／Lookup、规划／Plan、改写／Rewrite、提取／Extract、程序排错／Debug、执行动作／Act。按最终想得到的结果判主意图，不把领域或输出格式当意图。澄清是处理状态，不硬造第七类；接受明确的中英文别名，不用单个关键词或模糊子串判对。

| ID／原创请求，中英 | 亲手互动及正确主意图 | 歧义与反馈 |
| --- | --- | --- |
| T1：「先查 20:00 那班还有没有空位，别替我预订。」／“Check whether the 20:00 ride has a free seat. Do not book it.” | 拨动席位小景的查询道岔，看空位灯，不拉预订杆。**查询／Lookup** | 查找不等于执行；若拉预订杆，座位出现模拟预约带，提示“你预订了，但对方只想先查”，随后复原，不扣进度 |
| T2：「我想先看灯塔，再坐车，十点前回门口，帮我排顺序。」／“Plan a route: lighthouse, then the ride, back at the gate before ten.” | 在微型路线轨道摆出目标顺序，选择规划工具。**规划／Plan** | 不替访客购票；时间／地点若缺失可追问，本题给定园内地图和时刻背景，不额外考真实路线知识 |
| T3：「把‘禁止攀爬’说得客气些，但别改成允许攀爬。」／“Make ‘Do not climb’ more polite without changing the restriction.” | 把告示原件穿过改写滚筒，对照前后意思。**改写／Rewrite** | 改语气不等于改事实；不是先查询园规。装置输出是预写示例，不是实时语言模型 |
| T4：「从这张入园券提取日期、场次、人数，不要新增安排。」／“Extract the date, session and party size from this ticket. Add no new plans.” | 将票券送到提取装置，三个字段印章弹出。**提取／Extract** | 与 T1 共用票券造型，靠请求区分；JSON 等格式本身不决定分类，不脑补缺失字段 |
| T5：「小车程序一出发就重复回站，帮我找出逻辑错误并修正。」／“This cart program keeps returning to the station. Find and fix the logic error.” | 观察程序小景的循环，使用排错工具让错误节点可见。**程序排错／Debug** | 题目明确是程序，不误分为真实车辆维修；不要求玩家写代码，分类与短演示即可 |
| T6：「请替我预订 20:00 这一班的一个座位。」／“Book one seat on the 20:00 ride for me.” | 与 T1 相同席位小景，这次选择预订动作，模拟占一席。**执行动作／Act** | 场次、数量和请求已明确，不能只查完空位就算完成；仅园内虚构操作，无真实订票或外部发送 |
| T7：「帮我弄一下这个。」／“Can you sort this out for me?” | 先摇澄清铃，问“想改告示，还是订座？”；访客答“只把告示改礼貌，别发送”。再选**改写／Rewrite** | 初始信息不足，猜中标签也不直接计分；先澄清再判。选择查询、发送等错误后可纠正，保留其它题进度 |

T7 的追问与回复由作者写定，不随机改金标准。每题有稳定 ID、双语原话、必要背景、可接受主意图与反馈；别名只归一到这六类，不因“查找／执行都选上”而给分。

## 6．模型批次与最小输入输出契约

| 批次 | 可分工的产物 | 输入 → 输出与完成依据 |
| --- | --- | --- |
| I0 物资场逻辑 | 物件真值、遮挡／工具规则、合格与差异案例 | 不变的案例定义＋实际观察／开箱／转向／装载事件 → 独立数量、规格、质量与发货证据；不足时不能给“一致” |
| I1 物资场动作样板 | 一吊架、两钢卷、一秤一托盘、一车厢／货位 | 物件 ID、可达姿态、工具挂点 → 吊／开／照／量／装完成事件；真实接触与可见性由运行时核实，纯逻辑不冒充物理验收 |
| I2 扩成厂区 | 三棚、中庭、高廊、滚轮、吊架细节与标识 | I1 已成立的操作与尺寸 → 可选调查路线、全合格及差异两种完整循环；重复物资实例化，不先堆动态散件 |
| C0 意图逻辑／题库 | 七题、别名、澄清、六 unique 门槛、版本化本机进度 | 任务 ID＋分类／追问 → 明确反馈与正确集合；开箱→取钥匙→开门分别校验，持久化解析拒绝坏记录及不兼容版本 |
| C1 门外／乘坐切片 | 三类情境小景、宝箱、钥匙、门、列车、短轨 | C0 状态＋有接触的动作事件 → 箱盖／钥匙／门的可见变化；上车开始→轨道运动→安全回站，暂停不补播积压动作 |
| C2 大型完整轨道 | 抬升塔、骤降、反弯、灯廊、支撑及昼夜轮廓 | C1 的乘坐与回站契约 → 90～110 秒连续体验、可选低翻滚与退出；不在乘坐中插题 |

**逻辑侧的边界：** 物资模型维护唯一物件、规格、包装层级、单位和实际数量；标签与重量不能直接写成已核数量。装载必须有物件 ID 的事件，重复装载不增加件数，卸下后要更新当前车厢；货物改变会使之前发货确认失效。判定不变更案例答案，视线、开盖与工具条件未满足就返回原因。

**运行时契约：** 独立设施加载器接收设施 ID、局部出生点与本机进度，负责进入、返回岛上位置及卸载资源；不同时激活两套大场景。题库、物资纯逻辑不导入 React、Three、Rapier、浏览器存储或网络；调用方只在实际可达动作成立后发事件，负责把逻辑反馈呈现在物件附近。本机存储由调用方读写，纯逻辑只序列化／校验字符串，不静默覆盖损坏或版本不兼容的记录。

**开发顺序：** 先 I0／C0 和有意义的定向测试；随后 I1 与 C1 分别做独立样板，建模与运行重任务串行；再扩大到 I2／C2。主线性能修复与样板资源验证完成后，才把空间接回主岛。完成数据逻辑不等于完成场所，构建通过也不代替实际操作、听感和视觉验收。

首轮需验证：不同调查路径能得到一致结论；单独称重／看标签不误通过；全合格批次能正常放行；装载去重与卸货生效；错题可纠正、T7 必须先澄清、六 unique 才开箱；箱盖／钥匙／门顺序及本机版本校验；设施卸载不留下任务；乘坐可暂停与安全回站。视觉、可玩性、物理、性能和逻辑分别交证据，未做的项目保留未验。

# 泳池捕获预算与本机验证

后续更新：用户反馈低频倒影跳帧，已在 [移除场景倒影](water-no-mirror-20261027.md) 中删除该通道。本文保留当时的预算与测量记录，不代表当前倒影实现。

2026-10-27。基线 `2a17f8a`，性能提交 `80349b7`，来自隔离分支提交 `924af56`。这是一次有改善但尚未消除卡顿的性能修复。

## 改动

- 折射、倒影、焦散采用独立刷新时钟。流畅档上限分别为 15／6／8 Hz，高清为 30／15／15 Hz；远处继续降低预算。
- 流畅档离屏折射宽 640、倒影 320²；焦散网格从 32768 减至 8192 个三角形。主画布分辨率未改变。
- 限制折射为水下内容，保留浸水人物；缓存局部对象选择，辅助捕获不重复执行主场景 hooks，结束或异常时恢复渲染状态。
- 距离和画面占比连续淡出倒影；稳定暂停和离开 Club 后不再捕获。主水面与脚步波纹仍按已有公式运动。
- DEV 采样控件可比较两套都保留光学的捕获方式，记录额外 passes、draw calls、三角形和慢帧。没有常驻 UI 轮询或新 Worker。

## 定向验证

集成后 20 项测试通过：水面预算、异常恢复、暂停光照及画质切换、资源重复释放／重连、局部选择、入水交互。新设施规则另有 21 项定向测试及严格类型检查通过。

Chrome 单标签页，开发服务 4343，`qa=1`，流畅档，正午固定时间、晴天、音乐关闭。CSS 视口 1710×931，绘图缓冲 1951×1062。首次冷候选采样保留但不参与下表；随后原版与候选在同一池边观察点依次采样。镜头初始落地有轻微位置收敛，不把此实验称为严格硬件基准。系统处于内存压力 2，后台 CPU 负载波动。

按有效时长折算，额外 draw calls 减少约 37.7%，三角形提交量减少约 42.9%，对象选择访问减少约 87.0%。这些是本次局部 CPU／提交工作证据，不等于全帧 GPU 时间下降相同比例，也不等于普通生产入口稳定 60 fps。后续应在更稳定系统负载下复测普通入口、高清和长时间移动。

## 范围与挂载

默认导出 `src/components/world/attractions/WorldIbdYard.tsx`，在现有 R3F Canvas／Rapier Physics 下挂载 `<WorldIbdYard active={...} />`。组件自己使用 `IBD_YARD.center`，外层不要再平移。地面采用世界 y=1，薄地坪表面 y=1.08，范围 55×45 m。三棚、吊架、连通高廊、五金工位、滚轮与月台均为程序生成折面几何。

默认导出 `src/components/world/attractions/WorldIbdHud.tsx`，在现有 DOM HUD 层挂载 `<WorldIbdHud active={...} />`，样式由组件导入。两者只通过局部 Zustand store 共享状态，无 provider、新依赖、网络或存储接入。两组件均 memo；HUD 订阅厂区可见性布尔值和附近装置 ID，不订阅每次位置数组，避免园外 10 Hz 无效刷新。点击 HUD 按钮和 E／手柄 Y 使用相同的距离、高度、当前步骤与暂停检查。

`active=false` 时保留静态厂区与货物轮廓，撤销交互与标牌，冻结动作。隐藏页面、世界暂停、打开内容卡或检视模式也冻结动作，恢复时最多积算 0.05 秒，不补播暂停期间的时间。卸载解除交互登记，取消未完成动作，释放几何、材质、标牌 CanvasTexture；本次访问的已完成进度留在模块 store，刷新重置。没有本设施计时器或后台轮询。

使用现有 `WorldInteract` 注册，不新增键盘监听，不修改 `WorldActors`、`WorldRuntime`、`WorldApp`、全局 store 或 `attraction-layout.ts`。主线 south entrance `[-88,1.08,-150]` 及场外传送门 `[-101,1,-146]` 的落点区域保持开放。

## 纠错与重玩

四批顺序为全对、短装、后卷背面凹痕、规格 M6 冒充 M8 包装。全部是原创模拟资料，HUD、入口标牌和详情均说明，不代表真实客户或实际发现。

- 内件异常需开箱并完成检验，钢卷异常需核完两面，才提供「退换」；看标签或称重不能直接换货。
- 装错仍会实际装入车厢，不替玩家自动纠正。A／B 卸货杆分别为 `ibd-truck-a`、`ibd-truck-b`，脚底 `[-80,1.08,-168.5]`、`[-80,1.08,-160.5]`。卸回使先前发货确认失效。
- 退换保留原始物件、数量、规格、缺陷及已得证据，现场隔离位也保留原货。替换件使用新 ID，重新封箱／朝向复位，必须重新检查。后卷需要先吊走前卷，给退换托车留出真实通道。
- 原始案例只读；库存判定针对当前在库件，隔离旧货另记。发货只计当前真正装入车厢的两个唯一 ID，重复按键不重复装载。
- 确认发现少装或检查缺失会给出原因，允许补装、卸回、继续检验。只有库存与实际发货都一致才能升闸。
- 接货台主动作只查看／领取货单，不会误按 E 清空。附近 HUD 的明确次要按钮可重做本批或下一批；换批重置本设施的货物、证明与动作，不触碰其它设施。

## 文件责任与性能

`ibd-yard-game.ts` 包装现有 `ibd-model.ts`，负责空间动作、忙碌状态、完成提交、纠错和重玩。`ibd-yard-motion.ts` 提供可测的轨迹与暂停时钟。`ibd-yard-layout.ts` 只定义设施内部操作点并读取公共布局。`ibd-yard-store.ts` 是场景与 HUD 的桥接。几何、标牌、机构、HUD 与 CSS 分别独立；既有模型与四个案例文件未修改。

建筑为一份顶点色几何、一个主材质；标牌为一张 1024×1024 本地 Canvas atlas、一次绘制。四件货物和闸门为最多 5 个受控运动刚体，没有自由散件、真实光源、反射、外部模型或新 Worker。只有存在动作且设施可运行时，唯一 useFrame 回调才更新运动，React 不逐帧 setState。几何测试包含替换／隔离件，低于 70k 三角形预算。主通道预期最多约 14 个可见 mesh draw；这是结构计数，**不是实测 draw call、阴影提交或 FPS**。

静态碰撞由与建模同一组尺寸生成；高廊缓坡的平台入口已留出切口，避免平台压到斜坡形成卡腿台阶。两条滚轮线在中央人行道断开，车厢由短缓坡接驳。吊运有固定起落位，不能拖动物件堵住出口。

## 10 principles re-check

| 原则 | 本实现的具体选择 |
| --- | --- |
| 目的对齐 | `ibd-yard-game.ts` 按装置当前阶段给唯一主动作 |
| 减轻认知负担 | `WorldIbdHud.tsx` 只常显下一步、三项进度与当前反馈 |
| 状态可见 | `WorldIbdMechanisms.tsx` 展示吊、转、开盖、装卸，完成前不记证据 |
| 可纠正 | `ibd-yard-game.ts` 允许卸回、退换、重验、重玩，保留原始证据 |
| 可操作性 | 所有空间操作复用 `WorldInteract`，HUD 按钮同样检查可达性 |
| 界面退后 | 展开货单是可选阅读，正常流程不填表 |
| 无需手册 | 入口、三棚、缓坡、隔离位与装置均有物理标牌和下一步说明 |
| 尊重时间 | 受控动作不足四秒；无倒计时，错误不扣已完成检查 |
| 门槛透明 | 数量、质量与已装车分开，充分证据才给结论 |
| 单一主动作 | 附近装置一个主按钮，重开等操作降为明确次要按钮 |

## 实走反馈后的局部修复

主线报告坡顶胶囊中心 `[-111.90,5.90,-190.37]` 再向北移动后突然退到南侧并下落。原坡顶由互相拼接的薄盒组成，西侧落台只有 1.3 m 深；护栏没有碰撞。旧的无头检查只验证了预设点的静态净空，不能排除 swept movement 在薄盒接缝处遇到侧面法线。

本次把斜坡、北平台与侧廊改成同一份焊接顶点的闭合 Trimesh 薄壳，视觉与碰撞使用同一组顶面及边界，不在内部接缝保留竖直盒端面。坡宽 3.2 m，4 m 高差在 15.7 m 内完成，坡顶接 3.8 m 深的平落台，仍可使用上表脚底坐标。护栏补两道与可见横杆同尺寸的碰撞条，转入侧廊处保留开口，坡顶没有新增横穿通路的栏杆。

缓坡入口牌移至右侧，中心改为世界 `[-108.6,2.6,-172.97]`，增加匹配牌背与支柱的碰撞。HUD 根据已有 `sampleTimeLight(worldMinutes).night` 的昼夜状态在自身写入 `data-ibd-theme`，不依赖 WorldApp 中不存在的全站主题祖先；selector 返回稳定的 light／dark 字符串，不订阅位置数组。

三座棚的六块斜屋顶同步增加与可见盒体同尺寸、同旋转的碰撞，供主线镜头扫掠使用。根 group 的 `noOcclusionFade` 由主线添加，本分支未改该属性。

新增动态检查直接复用 `playerSupport`、`followPlayerGround`、`playerVelocityChange`、`sweptPlayerVelocity`，模拟正常上坡、上述坡顶坐标继续北行，以及带南向分量的横向移动；另以 0.25 m 相机球扫掠六块屋顶。6 项几何／运动检查和定向严格类型检查通过。尚未在真实主岛浏览器复测，不能据此断言已排除其它共享碰撞体或运行时因素。

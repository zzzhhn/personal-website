# v42 性能线只读复核

基线 `10df592`，隔离分支 `codex/perf-v42-audit`。本轮仅拥有本报告，不修改 integration 或运行源码。范围是国投四箱与单套活动卡规、Alpha 大厅／档案柜／回廊的进入、暂停、离开路径。

结论：未发现与旧车辆、标牌相同的大规模重复构建，也未找到足以确认新增累计资源泄漏的证据。保留两个低优先级、可以直接沿源码确认的无效帧工作问题；没有实测 CPU 节省量，不把它们称为当前卡顿根因。建议先处理第一项，第二项可随 Alpha 动态道具维护一起做。

## 1．P3：活动夹爪变化使非活动箱也重算隐藏机构

**触发与代码链。** 四箱尚未选走时，`WorldIbdMechanisms.tsx:127` 的前排箱和 `:142` 的两个后库箱各挂载一个 `WorldIbdPackInspection`。只有 owning 箱展开机构，这符合“单套活动卡规”的可见预算；不等于只挂载一个组件。

`ibd-pack-play.ts:105` 的物理 tick 在 measure／return 阶段持续更新全局 `ibdPackVisual.jaw`（`:116-123`）。`WorldIbdPackInspection.tsx:31` 只把非 owning 的 progress 归零，却仍把全局 index 和 jaw 放进每箱的 early-return 比较（`:35`）。因此活动夹爪每改变一次，另外至多三箱的比较也失败。

这些非 owning 箱仍执行 `ibdPackTransferPose`、三根杆的定位／旋转、`ibdPackInspectAnchors`、夹爪位置和槽位可见性更新（`:39-47`），尽管其 mechanism 在 `:38` 被明确隐藏。两个 helper 在 `ibd-pack-layout.ts:23`、`:40` 新建位置／锚点数组；这不是纯粹的一次空 callback 检查。

**后果与边界。** 多余工作集中在合拢、张开及换槽期间，最多三组隐藏机构跟随同一全局状态更新。空闲且状态稳定时现有 guard 有效；暂停／隐藏时物理 tick 在 `ibd-pack-play.ts:107` 返回，jaw 不再推进。不是四套同时可见、不是新增物理步，也没有证据说明这里占据大量帧时间。

**最小修复范围。** 仅 `WorldIbdPackInspection.tsx` 的状态比较。非 owning 箱不要因别箱的 jaw/index 改变而刷新；必须保留自身开盖／装载／父节点变化，以及 owning 从 true 变 false 后的一次归位清理。不要改卡规接触、样件身份或物理时钟，不必为了优化重做四箱资源架构。

**最小验证。** 用有界调用计数区分四箱 pose/anchor/setter：一箱从 jaw 0.54 合拢到 M8/M6 时，另外三箱稳定后应为零次姿态刷新；切换 owning、归位取消、选箱运输及卸载仍完成必要的一次更新。沿用现有卡规接触与四箱身份测试，再由主线选择是否做真实 UI 复核。先确认工作被消除，不提前承诺 FPS 提升。

## 2．P3：Alpha 静止道具在玩家离开后继续逐帧写同一姿态

**触发与代码链。** `WorldPark.tsx:124` 常驻挂载 `WorldAlphaExchange`，走出大厅／档案室不会卸载它。`WorldAlphaExchangePlay.tsx:75-94` 的 useFrame 只过滤暂停、卡片、shot、泳池检查及隐藏；没有动作或显示状态不变的过滤。

当 `exchangeBody.action === null`、round 与 carried 都不变时，仍每帧调用 `detent` 分配三元素数组，重复设置 slider、票／回执可见性、stamp、bell、pull、rope 的固定姿态。玩家在其它区域持续探索时仍执行这段相同工作。这里不涉及建筑几何重新生成、图集重画或真实灯数量增加。

**后果与边界。** 固定数量的小分配和 transform 写入；暂停／后台已有返回，不能说暂停仍持续运转。没有测得毫秒成本或 GPU 上传量。不可单凭这个 callback 推断视觉资源泄漏。

**最小修复范围。** 仅 `WorldAlphaExchangePlay.tsx`。在无动作且所需离散状态未变时跳过；记录 targetUnits、阶段、ticketReturned、carried 及动作结束／取消边沿，让结束后的静止状态应用一次。动作存在时保留原插值和接触表现。优先用状态变化判断，不增加距离轮询，也不卸载整个交易所来换取这点收益。

**最小验证。** 静止／离场且无动作的确定性帧序列中，首次同步后 setter 次数为零；取票、插票、拨杆、拉铃、压印、取消和动作完成后仍到正确终态。暂停中不更新，恢复后一次性同步；不得因跳过末帧留下悬空票、拉绳或压印头。无需为这个小问题先开全图性能采样。

以 `dcd6700` 和 [主岛矿区与线上联调记录](mainland-quarry-online-20261026.md) 为准：**WorldQuant 是真正挖因子的矿区，Alpha Agent 是历史交易所，DJC 是可蹦迪的露天 Club。** 不沿用旧 PRD 的“Alpha 即矿场”归属，也不改动这三处的既定方向。

这次要让访客走近后想亲手试一次，玩过一轮还能换个办法。候选都先给场所、动作与意外，再解释它与哪段真实经历相连；项目详情仍可直接访问，不用通关。下文时间、物件数量和难度均为小样目标，不是运行成绩。

## 方案一：Video Rebirth，一镜到底特技片场

**画面。** 海边是一座真的能跑进去的露天片场。铁轨摄影车、错位的屋顶、会翻转的街景立面和一颗夸张的大道具球，把一条短路做得像电影特技。玩家是上场的人，不是坐在影院里打分的评委。

**玩家行为链。** 推动摄影车到取景位 → 转动两块分离的布景，让取景框里的断桥看起来相接 → 按实体快门，布景实际转到可通行的位置 → 跑过桥，借转盘落到下一块平台，在滚来的道具球前撞响场记铃。取景只是一段短辅助观察，之后必须亲自走过；普通游戏视角仍要看得懂路。

**想再玩什么。** 先完成一个笨拙但连贯的长镜头，再试更顺的走位、另一个取景点或不被球追上的路线。布景背面藏着近路，第一次“穿帮”反而让玩家发现新的走法。跌落只落到安全网并就近重来，不清空整段搭建。可先保留一张终点构图，不承诺录像导出。

**经历联系。** 当前 [Video Rebirth 经历](../../../src/lib/i18n.ts) 涉及视频评测平台、视频采集、评测方法和首尾帧 prompt suite；[旧经历内容](../../../src/content/experiences/01-video-rebirth.md) 明确生成质量、指令遵循与语义一致性方向。这里把“单帧看似合理，连续动作是否成立”变成玩家能穿行的空间问题。特技机关是有意设计的游戏规则，不冒充某家公司模型的真实失效案例。

[EvalForge](../../../src/content/projects/evalforge.mdx) 可保留为相关独立项目入口，说明评测证据怎样被组织；不把独立公开项目、公司内部平台和这座虚构片场说成同一产品，不取用公司视频或机密评分体系。

**第一轮切片。** 一处摄影车、一座双段断桥、一块转盘、一颗道具球，约 90～150 秒形成完整尝试。先观察玩家是否会主动换站位找解法，以及成功接桥后是否真想跑过去；只有按键播放一段电影就不算。

**主要成本。** 美术中高：能从背面看、可运动且比例可信的布景，比一面漂亮贴图更贵。运行中高：移动平台接触、相机遮挡、玩家安全回收是重点；首版只保留少量受控道具，优先复用主相机的构图辅助，不开常驻第二视口、视频解码或生成任务。机关停止后不持续求解一堆动态碎片。离线只依赖已加载的自有场景资产。

**来源与推断边界。** 透视改变观察来自 Superliminal 官方文字；摄影车、实体接桥、追球与经历联系均是本项目提案，未在该游戏或 Gameplay Atlas 中实测。

## 方案二：字节 AIME，愿望会成真的小街

**画面。** 一条玩具般的街上，许愿精灵能让雨伞追着人跑、长椅托人上屋顶。玩家用手里的物件、站位和简单动作告诉它想发生什么，再亲自利用愿望变出来的路。看起来是胡闹的魔法，下面有能理解、能撤回的规则。

**玩家行为链。** 拿起雨伞，指向自己示意跟随 → 跑到雨廊，看到伞追来替自己遮住落下的彩球 → 把目标位置改到水池中央，示意停留 → 用停住的伞面当落脚点跳过去 → 回头让长椅托起另一端，拼出上屋顶的第二种办法。对象、跟随谁、在哪停住都在场内可见，不要求输入提示词。

**想再玩什么。** 同一个愿望作用到不同物件，会得到不同走法；两个仍有效的愿望叠起来，还可能出现一张追着人弹跳的长椅。玩家可以故意试这些可预测的荒唐组合，发现便捷路或搞笑失败。撤回一个愿望就能复原，不靠随机“听错”惩罚输入，也不让精灵无限自由发挥。

**经历联系。** 当前 [字节 AIME 经历](../../../src/lib/i18n.ts) 明确包含用户意图、理想回应、复杂指令、上下文问题与失败恢复。这个候选让玩家在身体动作中感受：换对象、目标或保留条件，结果就应跟着改变。它不是在搬运真实用户请求、给模型打标签或复刻评测流水线，更不宣称接入 AIME 或复现了工作中的自动化效果。

**第一轮切片。** 一条短街、雨伞与长椅两种物件、跟随／停留两类规则、一个屋顶终点。托举弹跳可先留到第二批。目标约 2 分钟内让玩家不看规则表也做出两种到达方式；若必须先读一页句法说明，应重做场景暗示。

**主要成本。** 美术中：物件需有能表达行为的动画与接触形态。逻辑中高：少量对象与规则组合也要防冲突、卡住和无限叠加；首版限制同时生效的愿望数量，角色移动与取消优先。运行成本主要在受控移动支撑面与临时特效，不在在线语言模型。效果暂停和离场后应停止，纯本地规则可离线玩。

**来源与推断边界。** 可改变规则的世界来自 Baba Is You 官方说明；手势、精灵和许愿街是改造推断，不复制文字积木。首版是公开标明的脚本 NPC，不把有限状态行为展示成真实 Agent 推理。

## 方案三：腾讯混元，记得你的捉迷藏搭档

**画面。** 一片有矮门、窗洞、花架和转角的花园里，住着一只会探头、招手的小搭档。它可以钻过玩家过不去的洞，玩家能把铃铛抛到它够不着的平台。两个人既互相帮忙，也轮流躲起来逗对方。

**玩家行为链。** 隔着矮墙抛铃，它从小门钻回来接力 → 给它看一次你选的目标铃，再把两只不同铃放到不同位置 → 绕到另一侧花架后藏起来 → 用窗上的影子、铃的响声或从窗口露出的物件引它寻找 → 看它从最后见过的位置出发，绕到真正能看见你的地方，找到后再换你找它。

**想再玩什么。** 试试同一个藏点能不能用不同线索找到、让它走另一条小路，或先制造一个有意思的假线索，再在它看向窗边时从背后绕出来。惊喜是搭档像记得刚才和你做过的事；笑点来自可读的寻找过程，不是忽然穿墙瞬移。它找错时会停下来重新观察，玩家能招手帮它，不必重开整轮。

**经历联系。** 当前 [腾讯混元经历](../../../src/lib/i18n.ts) 明确多轮记忆、视觉理解、CUA 和个人 Agent 体验评测。这个候选让“看见过什么、记住了什么、现在依据什么行动”成为捉迷藏的可见规则：搭档不能隔墙全知，也不能在换一个场景后无故忘记刚见过的目标。它与此前被否定的回声栈桥不同，核心是一个有观察边界、持续记忆和互补行动的搭档，不是回放玩家路线再贴项目名。

**第一轮切片。** 一座小花园、一只搭档、两只铃、三个藏点和一段互补通路。约 2～3 分钟完成一次接力、一次它找你和一次你找它；先检验玩家是否看得懂它为何转向、为何找错，并想换个藏点继续。无需先建设开放对话或生成任务系统。

**主要成本。** 动作与行为中高：探头、看向线索、寻找、找到后的回应，比纯路线跟随更重要。只用预制通路和少量可观察状态，感知按需要更新，不让每个 NPC 常驻高频视线查询。遮挡必须与可见岩墙／花架一致，不能用大量透明植被承担判断。复用已有资源管理，离开后停止寻找与音频；首版本地状态可离线玩。

**来源与推断边界。** 能力互补来自 It Takes Two 官方描述；单人搭档、捉迷藏、记忆规则均为原创改造。首版使用可解释的脚本状态，界面不写成混元模型实时驱动，也不把游戏表现用于声称真实模型分数或能力排名。

## 方案四：合拍，把选歌开成一段夜行山路

**画面。** 从露天 Club 外开走，一段短海岸路绕过山坡。下一个岔口还没到，两条路先飘来不同的下一首试听：一边鼓点更有劲，一边旋律更柔。玩家不是追拍点，而是在开出自己想听的下一段。

**玩家行为链。** 在出发处选一首种子曲 → 开到宽阔分岔前，听到两个已分析候选的短试听 → 用路线选择下一首 → 沿长弯听到真实双 Deck 转场与低频交接 → 在观景回环听完自己串出的短 Set，再从另一条支路试不同的能量走向。试听和确认也可停车完成；不要求驾驶中看长说明或按节奏键。

**想再玩什么。** 同样的驾驶路线，因为换了一首歌而有不同的情绪起伏；相同种子曲也能串成更平稳或更张扬的一段。错过一次岔路只继续听当前曲，下一处仍可选，不扣命、不强制重来。不兼容候选可以成为有意尝试，但不能用随机“契合度”分数假装算法推荐。

**项目联系。** [合拍项目内容](../../../src/content/projects/hepai.mdx) 本来就覆盖 BPM、调性、能量、风格兼容、播放序列和驾驶模式，并有浏览器双 Deck 转场。路线选择直接决定下一首与能量走势，联系落在真实产品的核心机制。**DJC 仍是上台操控和蹦迪的 Club，合拍在这里负责听什么、怎样连起来，两个项目不互相改名。** 音频能力的实际复用仍需下一轮读项目代码，不以 MDX 说明代替已接入证明。

**第一轮切片。** 复用一段现有可开的短回环，增加一次宽松分岔，三首已获准曲目，只做一次可试听选择与一次实际转场，约 60～90 秒。一开始不铺全岛音乐道路，不做竞速、漂移和选歌同时操作的复合关卡。

**主要成本。** 美术低到中，音频中高：时间调度、预载、音量过渡和驾驶焦点比新路牌更关键。先预分析少量曲目，限制预载与试听并发；不在行驶中跑全曲分析、下载分离模型或创建另一套常驻 AudioContext。声音必须由用户手势开始，隐藏／暂停时休眠；若没有合适音源或授权，明确缺失，不能用合成音替代后宣称听到了原项目推荐。离线能力取决于许可允许的随包音频是否已加载，不默认存在 QQ 音乐接口。

**来源与推断边界。** 少输入也能有音乐深度是从 Rhythm Doctor 官方定位得到的设计启发；道路分岔选曲、预听和驾驶约束是本项目推断。推荐与转场的事实依据是合拍自己的内容源，不是上述节奏游戏。

## 怎么收敛，先验证什么

| 候选 | 最有价值的小样问题 | 优先成本 | 保留意见 |
| --- | --- | --- | --- |
| 特技片场 | 透视解谜之后，玩家是否真的想进入并跑完那条路 | 场景／移动支撑面与镜头 | 画面最鲜明；若最后只有看构图、看演示，就偏离目标 |
| 许愿街 | 不读规则表，是否能理解并主动试第二种对象／动作组合 | 交互规则与可逆行为 | 与意图联系清楚，但最容易做成三维指令编辑器，需要先守住实物动作 |
| 捉迷藏搭档 | 玩家是否能读懂寻找过程，又愿意躲一次给它找 | NPC 动作、记忆与遮挡 | 与混元经历联系清楚；没有可信反应就不要扩大场景掩盖问题 |
| 合拍山路 | 一次路线选择是否真带来听得出的转场变化，且不打断驾驶 | 音频与驾驶输入协调 | 与产品联系最直接、切片较小；音频未核实前不承诺完整复用 |

- **地形组织是本项目推断。** 每处先让远处可见一个想去的物件，再用局部遮挡、近路和回望点形成探索；主路可直接经过，不强制串四个任务。不声称采用 GTA5 内部地图算法，不复制其地形或资产，也不扩写成全岛重排方案。

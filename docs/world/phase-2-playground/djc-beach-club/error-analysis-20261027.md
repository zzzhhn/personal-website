# Club 返工复盘，2026-10-27

本报告按用户指定的 `error-analysis` 工作流整理。主要问题不是缺少功能，而是数值检查和生成示意图替代了实际游戏中的视觉判断。以下把已定位原因、已完成修正和证据边界分开，不把新编舞称为新动捕，不把本机采样称为跨设备性能验收。

## 本轮发现并修正的具体错误

- 放大泳池后，旧数值夹具和几何共线边暴露问题。保留面积覆盖、退化面、台阶高度与连续通行要求，改用共享边界推导夹具；忽略面积近零的共线支持面，不放宽主要物理断言。
- 日床入口处在斜坡和圆形软垫边缘，导致真实动态角色受阻。将相关日床移到平整浅水区、延长入口，并让测试角色采用与生产相同的旋转锁定；八个方向的真实接近检查通过。
- 正式版绕池发现放大后两处出口不够易找，普通池沿会挡住人物。补为四处宽坡道，增加四个方向各两条走线的生产动态胶囊出水检查。测试同时修正了“出生时额外留空高度等于站稳高度”的错误假设：落脚依据实际胶囊半高与半径，仍检查到达外侧平台且真实着地。
- 第一版编舞触发膝关节速度限制。调整重心交换时序和幅度，保留原检查阈值。
- NPC 的测量最初漏掉肩部体积，真实解码检查失败后修正测量；最终换衣色时部件名未同步，测试失败后只更新识别名称，没有放宽比例断言。
- 曾误把来宾一段休息姿态怀疑为动画混合故障。按需读取实际权重后确认属于 16 拍乐句安排，随后在另一乐句观察到两位来宾均参与舞蹈。没有为错误假设添加补丁。
- 浏览器的可访问性树把 `aria-pressed` 按钮显示为 checkbox，且视觉上的空格不一定存在于 DOM 文本；猜测定位器导致一次超时。改用新读出的可访问性节点，不重复盲点。
- 个别路径猜测、shell 通配符和负数幂表达式引发短暂命令错误，均在运行前后检查并修正。后续用文件发现、限定路径和短日志取代整文件／库存输出。

## 性能和资源约束

本机检查为 memory pressure 2、可用磁盘约 9 GiB；swap 是历史累计指标，不能单独证明泄漏。本轮复用一个 Chrome 标签，序列执行构建与测试，没有再开 Blender、图像服务或新浏览器。

Club 动态视觉复用现有暂停感知时钟，没有增加 RAF、定时器、每灯阴影或实时反射摄像机。新增 NPC 检查仅在 DEV 且用户点击 QA 按钮时读取。暂停后实际观测到音频 context suspended、sources=0、拍数与 NPC 姿态时间保持不变。

开发页两次 180 帧采样分别为 p50／p95 17.6／19.6 ms 与 24.5／34.5 ms，拍摄角度和机器负载不同，不作前后性能改善比较，也不宣称稳定 60 FPS。正式构建的最终记录另见同目录验收说明。

## 防止重复问题的最小措施

1. 保留“活动下限 + 稳定上限”的舞步测试，以及外观对真实 G24 顶点的比例检查。
2. 场地相关数据继续从 `djc-club-layout.ts` 派生，使用真实动态角色验证进出和落脚。
3. 每项视觉修改保留常规距离、近景、夜间的实际画面，不能只交俯视概念图或程序计数。
4. 渲染、动画与音频的新增资源要有暂停、距离停更及释放路径；采样必须注明构建、视角和机器状态。

## 结论

1. **不是测量误差，也不是蒙皮混合造成的。** 6 个最差片段里，用骨骼踝点离线重建的位移和报告里的接触顶点位移基本一致（相差 0–1.8 cm，见下表）。这个重建只用骨骼头位置，不经过蒙皮，也不用 6 mm 接触阈值。所以滑步是姿态混合本身把脚移走了。
2. **Walk↔Run 的滑步是选错了切入相位**，可以靠最小代码修复。现在的匹配把两只踝的 3D 距离（包含高度）等权相加。它允许把源动作里正踩地的脚，接到目标动作里正在空中的那只脚上。另外，Walk 和 Run 的落脚位置本来就不重叠：Walk 落脚在 x≈+0.26，Run 落脚在 x≈+0.34…+0.41。所以 Run 刚落地时，Walk 里没有任何一帧能接上。
3. **Walk→Idle 的滑步不能靠相位、同速推进或调 fade 解决。** 切到 Idle 时根基本已经停住：0.1 s 渐变内根只移动约 0.4 cm，速度 ≤0.13 m/s。Idle 只有一个固定双脚站位，Walk 停下时的落脚点由松键时刻决定，两者在本地坐标里相差 0–25 cm，这个差只能由脚自己移动来消化。要真正解决，必须新增"收步"：手工制作的停步 clip，或运行时脚锁加 IK 加一步程序化收脚。两者都是新的可见行为，需要你和 Fable 决定。

补充实测：

- **减速阶段没有滑**：stop 段 Walk 帧里接触顶点的位移是 0.00–0.02 cm。Walk 的 timeScale 跟着实际位移降到 0.08，姿态在停下的相位上冻结，这一步是对的。

- **掉帧让跳变更集中**：434 个采样间隔里有 66 个大于 25 ms（最大 34 ms）。近档 Walk→Run 在 5.181→5.200 一帧内混合权重从 0.66 跳到 1.0，根也移动了 9.2 cm。掉帧把一次滑步压缩成一帧跳变，但不是根因。
- **鞋底补偿不影响水平位置**：Idle 渐变期间鞋底视觉补偿 `soleCorrection` 最高 1.53 cm，只改竖直方向，不影响水平位移，也没有掩盖滑步。

## 三个候选原因的判断

- **相位匹配**：这是 Walk↔Run 的原因。代码在 `WorldGuide.tsx:149–160`：对目标 clip 的 72 个样本，算 `left² + right²` 的 3D 距离取最小值。这个打分没有区分踩地脚和摆动脚，也不检查渐变结束时目标脚是否还在踩地。近档的 17.8 cm 就是把正落地的左脚接到了空中的左脚上：渐变先把脚抬起，Run 再在别处落脚。
- **蒙皮混合**：不是原因。只用骨骼的重建已经复现了位移。混合两条腿的旋转会让腿变短（所以需要那 1.5 cm 的竖直补偿），但这只影响高度。
- **脚接触测量**：不是原因。停步、起步、过渡三类最差片段，骨骼重建和顶点测量都一致。测量本身的局限：采样有限，阈值 6 mm，最低点会换顶点。这些都不改变上述数量级。

## Walk↔Run：最小代码修法（未验证建议）

目标：只在源动作踩地脚能连续踩地的窗口里切换，并且把这只脚接到目标动作里同样在踩地的帧上。代码位置：`WorldGuide.tsx:64–79`（预采样）和 `146–163`（切换）。

1. **预采样时记录踩地高度**：在 `phaseSamples` 循环里，记下每个 clip 的踝点最低高度 `stanceY[name]`。判断"踩地"用"踝高 ≤ stanceY + 0.006"。实测 Walk 最低 0.088，Run 0.092，Idle 0.095。
2. **切换时先判断踩地脚**：用现有 `left/right` 中较低的一只作为踩地脚。只有当这只脚在源 clip 中按当前 timeScale 推进 `fade` 秒后仍在踩地，才允许切换。
3. **按踩地脚匹配目标帧**：候选帧只取该脚在目标 clip 里正在踩地、并且推进 `fade × 目标 timeScale` 后仍在踩地的样本。距离只算水平 XZ，最小距离不超过 1.2 cm。
4. **有界等待**：找不到候选帧时推迟切换，源 clip 继续按现有方式随实际位移推进，最多推迟 0.2 s。超时后退回现有的两脚匹配，作为保底。

补丁草案（插入 `146` 行判断里，保留第 `161` 行的 crossFade 和第 `168–169` 行的 timeScale 推进）：

```ts
// setup (after phaseSamples): stanceY[name] = min over samples of min(left.y, right.y)
const isStance = (name: string, p: Vector3) => p.y <= rig.stanceY[name] + .006;
const sampleAt = (name: string, t: number) => rig.phaseSamples[name][Math.floor(((t % dur[name]) + dur[name]) % dur[name] / dur[name] * 72) % 72];
function plantedEntry(from: string, to: string, left: Vector3, right: Vector3, fade: number, fromScale: number, toScale: number) {
  const side = left.y <= right.y ? 'left' : 'right', foot = side === 'left' ? left : right;
  if (!isStance(from, foot) || !isStance(from, sampleAt(from, rig.actions[from].time + fade * fromScale)[side])) return null;
  let best: { t: number; d: number } | null = null;
  for (const s of rig.phaseSamples[to]) {
    if (!isStance(to, s[side]) || !isStance(to, sampleAt(to, s.time + fade * toScale)[side])) continue;
    const d = Math.hypot(s[side].x - foot.x, s[side].z - foot.z);
    if (!best || d < best.d) best = { t: s.time, d };
  }
  return best && best.d <= .012 ? best.t : null;
}
```

局限：

- **推迟期间的步频**：动作状态最多比物理晚 0.08–0.18 s。这段时间源 clip 按实际位移推进：Walk 在跑速下 timeScale 可达约 2.8，Run 在步速下约 0.42，步频会暂时偏快或偏慢，需要 Fable 看录像判断能否接受。
- **只解决水平方向**：不处理混合时腿变短的竖直问题，现有 2.5 cm 补偿保持不变。
- **前提有限**：没有覆盖斜坡，也没有覆盖转向中切换。模拟用的是线性位置混合，运行时是旋转 slerp，所以数值只能用来排序。

## Walk→Idle：为什么调参不够，必须新增收步或 IK

以下推导都基于实测和 clip 数据。

1. **根已经停了**：切 Idle 的阈值是 0.12 m/s（`WorldGuide.tsx:145`）。到这个时刻减速基本结束，0.1 s 渐变里根只移动约 0.4 cm，只占观测滑步的 2–4%。所以问题不在"根和脚不同步"，同速推进没有可修的东西。
2. **Idle 的站位是固定的**：Idle 的 2.4 s 循环里，双脚踝点始终在 x=+0.015、z=±0.108。Walk 的踩地脚在一个支撑期内从 x=+0.263 移到 −0.093，刚落地的脚在 +0.26–0.28。只有在支撑期中段约 1/15 周期的位置，踩地脚才离 Idle 目标 3 cm 以内，而那时另一只脚正处在摆动最高点，比地面高约 9 cm。Walk 里没有任何时刻能让双脚同时落在 Idle 站位上。
3. **停下的相位由松键时刻决定，无法再推进**：Walk 随实际位移推进，这正是减速段不滑的原因。但从松键到停住，根只走约 0.12–0.15 m，Walk 只能再推进约 0.08–0.1 s，也就是约 1/6 周期，到不了一个合适的站位。要让 Walk 继续往前走到合适相位，只有两条路：脱离位移推进（脚会重新开始滑），或者让根多走一段（改刹停距离，属于玩法和物理改动，不在范围内）。离线模拟里"推迟到摆动脚落地再切 Idle"也没有改善，最大 27.6 cm。
4. **缩短 fade 或低速直接切，只是把滑步变成瞬移**：同样 8–25 cm 的脚位差会压缩到更少的帧里显示。Fable 20:47 已经确认这样不行。

近似模拟里，24 个松键相位的停步滑移是中位 11.4 / p90 24.1 / 最大 24.1 cm，覆盖了实测的 10.55 和 22.96 cm。只要还是"冻结的 Walk 姿态混合到固定 Idle"，无论怎么调参数，这个分布都不会变。

### 可选方案（需要你和 Fable 决定）

**A. 手工制作的停步 clip**：比如 `StopL` / `StopR`，或者按落脚相位分成两三段。
- 做法：踩地脚保持不动，另一只脚收到 Idle 站位，盆骨回到中间。运行时按停步时哪只脚踩地、在什么相位来选择。
- 优点：动作可控、美术可审、运行时简单。
- 代价：要改 G24 rig/GLB，并重新走一遍 rig-animation-smoke 的导出和回读检查。本轮禁止改 GLB/rig，所以需要单独授权。

**B. 运行时脚锁 + 双骨 IK + 一步程序化收脚**：rig 每侧有 thigh/shin/foot，可以做解析双骨 IK。
- 做法：
  - 切 Idle 时记录踩地脚的世界位置。在第 `170` 行 `mixer.update` 之后、第 `171` 行竖直补偿之前，用 IK 把它钉住。
  - 偏离 Idle 目标超过约 3 cm 的脚，用 0.25–0.35 s 抬脚 6–8 cm、走一段弧线收到 Idle 目标，然后释放 IK。
  - 两只脚都偏时，先收远的那只，一次只动一只。
- 局限：
  - 膝盖方向需要指定。
  - 腿可能够不着。脚在前方 25 cm、盆骨在 Idle 高度时能否够到，没有核实；够不着就必须降低盆骨或改成先迈步，否则会残留滑步。
  - 不处理脚掌翻转。
  - 只适用于平地，斜坡没有地面目标。
  - 和现有 2.5 cm 竖直补偿会冲突，需要调整执行顺序或去掉补偿。
  - 原地转身时脚锁必须释放或转成迈步。转身弧长问题按 Fable 意见只记录，所以这一点要和他对齐。
- 这也是新的可见动作（停下后多一步），需要 Fable 按录像验收。

**C. 只做脚锁，不收脚（不推荐单独使用）**：角色会以停步时的前后错开站位进入 Idle，双脚前后最多相差约 37 cm（推算），看起来像定格在半步里；如果之后原地转向，问题会继续放大。

**明确不可行**：继续调 fade、阈值、timeScale 或相位门限。理由见上面 1–4。

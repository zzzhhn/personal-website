# G24 已发布 d3 版本：身体壳相交复查（未通过）

2026-10-21 对 75d2f9c 中的 G24 native 和实际发布 Draco GLB 进行独立只读复查，GLB SHA256 `d3ccc5919af10f6614e91c3d31d548c6135bb4c0ba29dbaca6da558c0ac89357`。该版不能通过角色几何门。

此前 README 将 `BVHTree.overlap()` 描述为只检查包围盒，这是错误解释。[Blender v4.2.23 官方源码](https://github.com/blender/blender/blob/v4.2.23/source/blender/python/mathutils/mathutils_bvhtree.cc#L485-L513) 的回调调用 `isect_tri_tri_v3`。本轮先三角化实际评估表面，再用独立的线段/三角面求交定位交点，报告内保存三角坐标、交点和发生时刻。

每份文件均采样 521 个整数与半关键帧（60 Hz clip，120 Hz 检查），只检查连续身体壳，不把有意嵌入的靴/头盔/腰包当成同壳自交。最长相交线约4.94cm；**交线长度不等于穿透深度**。原报告10/20是polygon去重口径，本表是triangle口径，不可直接比较成“多了多少缺陷”。

GLB材质接缝和分primitive Draco量化会拆顶点。只在内存审查副本中按10微米重接，恢复1025总顶点、416身体顶点、11壳，与native一致，不写回资产。第一次0.1微米不足以接回身体，误把201顶点头盔选成最大组件，产生无效0结果；该报告保留为 `d3-glb-seam-split-invalid.json`，**不能作为通过证据**。脚本已增加pelvis权重身份检查避免此误判。

局限：使用浮点几何；共享顶点的邻面排除；没有给出全部共面/退化情形的数学保证，也不检测所有刚性件之间的接触。但已找到的非共面交线足以否定本版本的身体壳无自交。Native与GLB三角面计数不同可能受变形后的quad三角化与导出固定三角连接影响，最终门以实际GLB为准。

角色会话已接收定位结果，返修中。旧motion-r4的4/4仅证明其明列的状态切换/鞋底/运行指标，不覆盖内部关节表面，不得用它抹平此次失败。修复后须绑定新hash重新做几何和受影响的动作专项；无需重跑未改变的全岛连接或碰撞批次。

Fable 已直接收到纠错并确认 d3 的 A 不通过，新增 A6 按关系表检查。`d3-glb-all-shells.json` 同时检查11个独立闭壳自身，计数与身体壳检查相同；未发现其余独立壳自身的非共面交线。这不覆盖跨部件有意嵌入和非预期碰撞，二者须按新关系表另查。

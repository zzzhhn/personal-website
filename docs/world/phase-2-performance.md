# 长期任务：性能与资源效率

2026-10-25，Bobby 要求将性能与电脑资源利用作为本项目的长期任务。目标是持续游玩流畅、输入及时，用户暂停、切到后台或离开时能让出资源；新增内容不应引入无意义的负载。当前是任务定义与源码线索，不是性能认证。

## 什么算做好

| 场景 | 应有表现与检查 |
| --- | --- |
| 前台游玩 | 步行、驾驶、营地、城区、展品与昼夜切换均测帧时间分布、卡顿和输入响应；同时观察 CPU／GPU 开销，不能只报平均 FPS。首轮以 60 fps 为体验目标，设备、档位和可持续预算按实测建立，不冒称所有电脑保证 60 fps。 |
| 暂停与后台 | 无需更新的物理、动画、音频、渲染和轮询应停下或按需求运行。稳定后不应维持游戏级负载；恢复不能暴冲、补算积压帧或同时启动重复循环。菜单交互和必要重绘仍正常。 |
| 长时间与反复进出 | 一次有边界的持续试玩，以及反复进入／离开、音频开启／关闭、上下车和复位后，检查堆内存、GPU 对象计数、监听器、定时器、音频上下文和项目创建的 Worker 是否累积。区分有界缓存、垃圾回收波动与持续增长。 |
| 离开页面 | 本页面拥有的循环、订阅、音频与 Worker 结束，独占 GPU 资源按所有权释放；不能误释放仍被共享的 GLTF 资源。包括可适用的前后退缓存和热重载路径，但开发模式数据不冒充正式构建结果。 |
| 加载与设备差异 | 分开冷加载与暖机，检查资源体积、重复下载、解码和编译峰值。画质档位应有明确成本；保留观感与手感，按瓶颈调节，不能只有降分辨率一招。 |

线程数不是单独的优劣指标。只审计本页面创建的 Worker、并行任务和重复工作；浏览器辅助进程、GPU 进程或其他程序的线程不能直接归因于网站。浏览器无法可靠提供的 CPU／GPU／显存／能耗数据，应标为未测，必要时用系统工具补测，不伪造跨浏览器的统一百分比。

## 第一轮怎么做

1. 从当前已合成版本建立源码清单与可复测路线，按影响、证据和改动风险排序。优先找暂停后仍在工作、订阅未释放、重复调度和持续增长问题。
2. 串行测正式构建的普通入口，记录提交、浏览器、设备、视口、DPR、画质、冷暖状态、时长与当时系统负载。已有 QA 工具可辅助定位；不能把 QA 固定机位或开发服务器的开销当作普通用户结论。
3. 对最有证据的一两个问题做小改动，以同条件前后对比验证，同时复查对应玩法与画面。主 session 审核跨人物、驾驶和美术的共享文件。
4. 将关键检查变成轻量回归。建立基线后，根据测量波动设定回归容差；尚无实测前不写武断的 CPU／内存上限，也不沿用旧灰盒预算当新版本成绩。

首轮持续运行观察可从 10 分钟与 5 次进入／离开开始；只用于发现趋势，若发现增长再定向延长，不进行无期限压测。低资源时先做源码审计与计划，不把整机压力归咎于网站，也不在压力下生成具有误导性的基准。

### 首轮源码审计结论

2026-10-25，性能 session 已完成只读审计，主 session 已检查报告及关键源码。优先项依次是：暂停后的持续渲染、音频所有者清理与调度、全量 store 订阅带来的 UI 重算、暂停或提示完成后的 UI 手柄轮询。已安装 R3F 默认 always；位置约每 0.09 秒发布一次，而 WorldApp 订阅整个状态。后者不等于 memo 化的 3D 场景全量重建，所有实际耗时仍未测。

建议下一轮先给暂停场景增加按需渲染，保留菜单昼夜渐变、画质切换和缩放需要的有限重绘，再比较同机位前台运行与暂停各 60 秒，复查恢复后的输入、车辆和音频。不能只切换 Canvas 属性而忽略渐变时钟，也不能把暂停 Canvas 等同于整个页面已休眠。

音频单例已有 started 防重复启动；暂未证明重复按 DJ 会创建多个上下文，也未测得持续泄漏。应分别验证同文档卸载、普通整页导航和适用的 HMR／前后退缓存路径。以上为实施前的源码审计结论。

## 长期协作规则

- 人物、驾驶、美术、新地图和小游戏的交付都要说明新增常驻任务、资源生命周期与受影响性能；按改动范围复测，不要求每个小改重跑全岛。
- 测量、优化、观感回归和用户体验分别记录。每次报告给出同口径前后数据、已知限制与未测设备，不能用“感觉不卡”代替证据。
- 性能线首轮拥有审计记录与测试建议；运行时代码触点由主 session 协调后再分配，避免与其他 session 同时重写共享文件。
- 本机资源预检与重型任务锁沿用 [协作说明](phase-2-coordination.md)。不增加常驻监控服务，不采集或上传访客设备指纹，不清理用户无关进程或文件。
- 任务持续伴随版本迭代；某次样本通过只代表该提交和测试条件，不表示长期任务可以永久关闭。

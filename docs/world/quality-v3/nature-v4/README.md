## 2. 技能流程（每件都跑）

生成 `build_nature_v4.py`（导出到 staging）→ `qa_v4.py`：原生 blend 与 Draco GLB 在新场景回读，比对三角数、包围盒（差值 < 1e-4 m）、有限坐标、退化/重复面、硬件闭合流形、树木连续、叶根埋入、接地、居中、无摄影棚对象、`_WIND` 保留、≈2N。8/8 全部为 true → `render_views_v4.py` 从回读 GLB 渲染（`views/raw/`）→ `promote_v4.py` 校验哈希后才拷入 `public/`。Blender 4.2.23 LTS；它在沙箱内会因 Metal 探测段错误，需要提权运行。

## 3. 交互分类（§11.3 收窄版，已实现）

| 类 | 对象 | 实现 |
| --- | --- | --- |
| 可穿过有阻力 | **只有 G19、G20** | 与视觉同源变换的凸包传感器（取整个树冠顶点），没有刚体内核 |
| 可推动小物件 | **只有现有的 4 个 28 kg 橙色路障**（`WorldObstacles`） | 不改动，bot 复证可推动 |
| 坚硬不可穿 | 树干 G16–G18、岩石 G21–G23（G23 保留原 solid 可跨越口径）、长凳 C06、火圈 C05、帐篷 C03/C04、桌 C07、书堆 C08、奖杯架 C09、旗杆 C10、C11–C15 占位 | 不改动 |

建议（未实现，不自动改类）：日后若加入高草、芦苇、布帘，可复用同一阻力区；轻桶、锥、木箱可沿用路障的动态刚体做法；帐篷弹性外层这轮不做。

阻力算法（`WorldCampPhysics.tsx` 的 `SoftBushDrag`）：每个物理步对与传感器相交的动态刚体只施加水平冲量 `-v_h·(1-e^{-k·dt})·m`，`dt` 取实际 timestep；人 k = 5.6/s，车 k = 0.8/s。重叠灌木取 max(k)，不叠加。y 分量恒为 0，不改重力和悬挂；离开即停。`WorldActors` 的脚底、地面、悬挂、出车射线都已有 `!c.isSensor()` 过滤（已逐条确认：`castRayAndGetNormal` ×4、悬挂 `updateVehicle` 过滤、`intersectionsWithShape` ×2、`castShape` ×2），所以传感器不会被当成支撑面。**不需要改 WorldActors**。

视觉：推开与恢复由同一个物理步写入 `pushUniforms`（最多 4 个物体）。叶片按高度权重被推离 ≤ 0.32 m，离开后以衰减振荡在约 1.6 s 内回位。颜色、depth、distance 三个 pass 使用同一位移，所以影子会跟着动。风动保留，并叠加在推开位移之上。

## 6. 美术判断（我的意见，不是通过结论）

- 树：树冠从“几个大多面体”变成可以辨认的叶簇层次，三棵树的轮廓和高度不同。但这一轮树之间的偏色差异只来自原有三阶分布，没有为每个实例另外偏色。
- 岩石：台阶、倒角和苔藓斑在近景能看出来。苔藓呈三角块状，面积偏大的那面在 G21 上略显生硬，需要人看。
- 火焰：从“橙色锥子”变成多条火舌加色带加火星，近景读得出来；远景是否够亮要在夜档实玩判断。
- 灌木推开：`bush-push/sheet.png`（前、区内、离开 +0.3 s、+1.8 s）。俯视机位下推开幅度可见但不夸张，需要实玩确认手感。

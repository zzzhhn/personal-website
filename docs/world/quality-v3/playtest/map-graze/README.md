# 地图原位轮胎侧擦（map-graze）· 结果：0 例轮胎通过，全部是覆盖缺口

脚本：`tools/world/playtest/map-graze.mjs`。只读运行，没有修改任何 src。

## 运行方式

- **加载与冻结**：URL 是 `?qa=1&qaWheelGuards=1&qaLowCom=1`。`page.goto` 之前先用 `page.routeWebSocket` 切断 HMR，整次运行都用最初加载的代码。
- **每例的流程**：
  1. 三辆车都停回各自的停车位，避免前车挡路。
  2. 只摆放一次起点，用 `teleportVehicle` 和 `fixtureTeleport`，全部记录在 `fixtures`。
  3. 按 E 上车。
  4. 只用 W 和 Space 控制，把速度保持在目标值附近。
- **判定**：
  - `tyre-pass`：视觉轮胎圆柱和目标的距离 < 5 cm，并且撞前速度在目标 ±15%（最少 ±0.5）以内、穿入 ≤ 5 cm、抬车 ≤ 15 cm、没有翻车。
  - `partial-body-or-guard-only`：车身或轮护（guard）和目标有接触，但视觉轮胎从来没进入 5 cm 内。这种情况算覆盖缺口，不算轮胎通过。
  - `not-reached`：目标根本没被接近。
- **代码版本**：每份报告的 `codeVersion` 里有运行开始时 `WorldActors.tsx` 的 sha256，以及当时的质心那一行代码。两次有效运行时的质心都是：offroad/van 下移 0.5 m，coupe 下移 0.3 m。
  - `report.json`（G18 与 G16）：`ed1f7e8a…`
  - `report-lamp-post-rerun.json`：`3cc55b54…`

- **车都被拦下来了**：三类目标的 27 例里，车都在目标处被挡停（`blocked`），实际是车身或轮护先接触。在设定的 8 cm 侧擦深度下，视觉轮胎一次都没有进入 5 cm 内。
- **没有异常动作**：没有翻车，没有弹飞；抬车最大 10.9 cm（灯柱，coupe/offroad 在 10 m/s 档，实际速度约 5 m/s）。
- **轮胎侧碰本身没有被测到**：这些数字说明不了「轮胎侧碰代理」表现如何，只能说明在这些地图位置，车身或轮护比轮胎先挡住。

## 关键测量限制：轮胎探针测不到树干

把 offroad 的 1 号轮中心直接放在 G18 树干轴线上（`/tmp/sh/mg-probe6.mjs`），`motionProbe` 返回的 `nearby` 是空的。同样放在灯柱中心，读到的是 −0.275 m，说明灯柱能测到。

营地树干的碰撞体现在是 trimesh 闭壳（`campColliders().kind === 'trimesh'`）。轮胎圆柱整个在壳内或者擦着壳面时，`contactShape` 不返回接触。所以对 G16、G17、G18 树干，现在的探针无法给出视觉轮胎的有符号距离，就算轮胎真的擦到了也会读成「没有」。

这是需要主线程处理的探针缺口。可选做法：用 `castShape` 或 `intersectionsWithShape` 加上壳内判断，或者让树干改用凸包碰撞。改之前，任何树干侧擦都不能判为轮胎通过。

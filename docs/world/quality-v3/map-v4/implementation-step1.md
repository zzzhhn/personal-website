**状态**：代码已经接入，只在 `?layout=v4` 下生效；默认入口仍是 v3 布局。§12.6 规定的受影响集合**还没跑**，要等主线程通知切换默认入口以后跑一次。下面所说的「通过」只是平面几何测试和编译，不是通行、物理、视觉或性能验收。

## 1. 开关与默认入口

- 开关在 `src/components/world/layout-v4-flag.ts`。`?layout=v4` 打开 v4，把 `DEFAULT_V4 = true` 改成默认后，可以用 `?layout=v3` 切回旧布局。这个文件不做任何几何计算。
- 默认入口的布局和行为不变：旧文件里的每个 v4 分支都只是数据替换或者 `if (!LAYOUT_V4)`，v3 下的取值和原来逐字一致。`actor-physics.test.mjs` 2/2 通过；dev 4322 上无头检查默认入口：轿跑仍在 (19.8, 12)，旧路正常渲染，没有 v4 组，没有页面错误。
- **默认入口并非完全没有 v4 成本**：`WorldDistricts`（铺装、体块、家具、碰撞）是单独的懒加载块，默认入口不会请求。但 `layout.ts` 静态引入了 `layout-v4.ts` 的道路中心线（为了在 v4 下同步给出 `ROAD_POINTS`），所以初始 UI 包里多了这部分代码。压缩后 `layout.ts` 打包从 1.3 KB 变成约 5.3 KB（gzip，已经用 `__PURE__` 把重几何摇掉），模块评估约 5 ms（Node，本机）。铺装、体块和家具等重几何只在 v4 下首次使用时生成。如果要做到零成本，可以把全网折线移到没有依赖的小文件，这次没有做。
- v3 入口在 dev 4322 上的统计跟改动前同一量级（见 §5），没有单独重跑 v3 的回归。

## 4. 地形现状（开关下、接入补丁以前）

`WorldLandform` 读 `ISLAND_OUTLINE` 和 `ROAD_POINTS`，所以 v4 下它已经直接生成新轮廓的沙滩、泡沫和落水回岸，沿全网的草和地表起伏也会避开道路。剩下的已知差距：

1. 网格范围还是旧的（z ≥ −104），北端约 4 m 的陆地和一段沙滩被截断。
2. 北丘由 `WorldDistricts` 临时补一块地形（与主地形用同样的 surface/solid 碰撞划分），山脚外圈会有草穿出坡面。
3. 城区海堤仍是 v3 的 `townFactor` 矩形。
4. 新体块、空地、楼前广场和停车场里还会长草；旧内陆灰块的位置会留下无草方块。
5. 新北岸和西岸的落水采样点都能找到干地（离线 `nearestDryPoint` 全部命中），结果记在 `smoke/` 和 §6 的检查脚本里。真实回岸和支撑仍要留到 §7 集合里验证。

## 7. 切换默认入口以后跑一次的受影响集合

```bash
WORLD_LAYOUT=v4 WORLD_PLAYTEST_DIR=docs/world/quality-v3/playtest/drive-route-v4 node tools/world/playtest/drive-route.mjs
```

（切换以后 `WORLD_LAYOUT` 可以省略；不加该变量就走 v3 的原有用例。）用例：

1. 时间轴路线：三车从营地出口开到园区 (49, −46)，路线读自 layout，只在前方确实是弯道时才减速，并记录沿途接触到的 solid/obstacle。
2. 三车环岛一圈（环岛路加大道，414 m）。
3. 越野车上山再返回：要求最高点超过山顶 0.4 m，并回到 J5。
4. 新岸五个采样点（北、西北、西、西南、南）各做一次玩家落水和一次小货车落水，分别记录「干地命中」和「道路回退」，并用向下射线确认落点下面是 surface、不在水面上。不再只看 y > 0。
5. 家具接触：分隔柱、路灯、停车牌、红绿灯各一件，小货车以约 5 m/s 直撞。要求撞前家具处于休眠、撞后位移 > 0.3 m、车身上抬 ≤ 15 cm，并记录此时唤醒的家具数。

继续保留的已知失败：原车控轮胎穿低柱 9 cm、撞路障时车身上抬。可撞家具比以前多了 56 件，这两项暴露的机会更多。`gaps.mjs`、`map-graze.mjs` 已改为读取轿跑车位，但它们的碰撞目标还在营地里，不属于本次集合。

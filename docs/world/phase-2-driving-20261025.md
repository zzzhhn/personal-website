# Phase 2 驾驶样板，2026-10-25

工作分支：`codex/world-phase2-driving`。基线：`3cb1f25`。本轮以 coupe 轿跑为标杆，其他两车保留原有动力学。只做本地实现与验证，不推送、合并或部署。

## 可试玩变化

- 轿跑使用逐渐建立的驱动力和极速附近的连续收力，取消原来的硬开关限速；前后轮按 36／64 分配动力。降低车身线性阻尼，松油后保留更多惯性，制动由脚刹和轮胎承担。
- 低速保留大转角，高速按横向加速度限制转角；普通过弯不再无条件削减后轮抓地。根据实际侧滑提供有限反打和偏航力矩辅助，空中不施加辅助，不直接改写车速或朝向。
- 脚刹前后分配，反向油门先减速再倒车。X 手刹降低后轮抓地并制动，松开后逐渐恢复抓地，可以用反打和油门控制出弯。
- Shift 氮气约三秒。车身前进、车轮有支撑、未刹车时才启用；耗尽后持续按住不能循环触发，松键且冷却结束后恢复，完整恢复约九秒。
- 加大轿跑悬挂压缩与回弹阻尼，保留真实车轮升降和车身俯仰。氮气让追尾镜头额外扩展 4°；第一人称保留 70°。
- 轻量程序合成引擎、轮胎摩擦和氮气音效，无外部素材。暂停、切走页面、下车时静音，卸载时释放 AudioContext。

操作：W／S 油门与倒车，A／D 转向，Space 脚刹，X 手刹，Shift 氮气，E 上下车。手柄沿用 RT／LT 驾驶、左摇杆转向，X 手刹、A 氮气。新特性仅限轿跑，说明已写入中英文 `world-i18n.ts`。

## 与主线集成

普通运行时接口在 `src/components/world/vehicle-telemetry.ts`：

```ts
import { readDrivingTelemetry } from './vehicle-telemetry';
const driving = readDrivingTelemetry();
// null，或 { id:'coupe', nitro:0..1, boosting, handbrake, braking,
//   slipAngle:弧度, contacts:0..4, speed:有符号米/秒, power:-1..1 }
```

每个物理步发布，HUD 可每 100 ms 读取。上车前、下车后返回 null。没有修改 store 或 HUD 组件；QA snapshot 额外包含车轮悬挂长度和动力诊断。

`WorldActors.tsx` 合并触点：

1. `enter()` 的 `clearInput()` 附近保留当前驾驶按键，但清零轴、动力和一次性动作，避免按住 W 上车后丢失当前意图。
2. 控制区只判断 `guideTransition.current?.phase === 'enter'`。入座期间清零动力，抑制油门、倒车、转向、手刹和氮气并保持脚刹；车辆仍由正常碰撞求解。人物线的 elapsed 与阶段清除时机是唯一时钟，驾驶线不自计时。
3. `clearInput()` 同时清除待发动力和反馈状态，取消或退出不会补发。人物线的排队退出和暂停时序由主线合并后复验。
4. 车辆初始化、snapshot 车辆字段、驾驶循环、氮气 FOV 和反馈组件挂载点。没有重写人物控制或更换模型。

## 验证

已串行执行实际 Rapier 回归：`vehicle-driving`、`actor-physics`、`player-ground`、`layout-v4`，20 项原有检查和 7 项驾驶检查通过。新样板使用同一运行时控制函数、正常凸包、质量和重心。

| 平地固定 60 Hz 对比 | 基线 | 本轮轿跑 |
| --- | ---: | ---: |
| 0～60 km/h | 2.300 秒 | 2.833 秒 |
| 60 km/h 到低于 0.2 m/s | 2.167 秒 | 1.700 秒 |
| 同条件制停距离 | 17.375 米 | 14.045 米 |

这些是明确初始条件的物理测试，不能当作浏览器主观手感或所有路面下的保证。测试还覆盖手刹相对普通过弯产生更大侧滑、松开后回收、全舵不翻车、12 cm 接缝后恢复四轮支撑、空中保留动量且不消耗氮气。

验证中修复两项实际问题：刹车必须把发动机力精确置零，避免 Rapier 优先采用残余驱动力；车辆射线使用 `QueryFilterFlags` 排除 sensor／动态／运动学支撑，避免 predicate 内嵌套 `isSensor()` 查询导致当前 Rapier 的 collider set 保持借用、`world.free()` 失败。已用最小场景复现，替换后测试世界正常释放。人物与其他查询不在本轮修改范围。

`npm run check`：259 文件，0 errors、0 warnings、135 hints。`npm run build`：主页与 world 两页通过，临时试驾入口在构建前移除。`git diff --check` 通过。

Chrome 复用既有实例，只开一个试驾渲染页，Balanced 档，临时服务为 4343，独立 Vite 缓存与允许共享依赖的临时配置不提交。真实键盘试驾已执行：

- 持续 W／Shift，fixture 在 1.6 秒后调用正常 `enter()`，采到的入座窗口发动机力为 0、氮气为 1；入座完成后峰值 21.610 m/s，氮气最低 0.356，随后脚刹停稳。这里明确是定时入座 fixture，行驶输入来自真实键盘，不冒充完整普通入口流程。
- 普通 E 键入座、W 加速、A／X 手刹起滑；短按 0.55 秒手刹后使用 D／W 反打，再给油 0.9 秒，采样得到 15.458 m/s、侧滑角约 0°、四轮接地、后轮抓地恢复至 0.9998。这证明本轮能完成起滑与收回，不代表所有速度和输入组合都已调好。
- 正常轿跑停车湾 `[26.2, 2.194, 2]` 出发，实际 W／A 沿海岸大道前进并脚刹停在约 `[19.43, 2.14, -27.69]`，车速低于 0.005 m/s，四轮支撑。起点由 fixture 设置，途中驾驶没有 teleport 或 drive() 控制。
- 已坐好后 Esc 暂停，W／Shift 不产生驾驶输入，恢复后可正常 E 下车；旧基线入座中短按 W／Shift 后 E 退出，车辆保持在起点，发动机力为 0、氮气为 1、无待补发输入。

五段 20 秒记录共 1,970 个样本，56 个入座样本全部为零发动机力、满氮气。暂停探针 38 个样本停在同一 physicsStep，输入为空、发动机力为零。浏览器未捕获 error 日志。精简指标与关键原始样本在 [summary.json](phase-2-driving-evidence-20261025/summary.json)，运行画面在 [coast-coupe.jpg](phase-2-driving-evidence-20261025/coast-coupe.jpg)。完整 4.9 MiB 本机记录保留在本工作区 `.astro/driving-runtime.json`，精简报告包含它的 SHA-256；完整记录不提交。

本分支人物仍是原基线的 0.7 秒时序。人物线 elapsed、1.15 秒入座、排队退出、暂停后继续入座与安全落脚，必须由主线合并后组合复测，未记为通过。

## 尚需接受与后续

- 本轮物理模型属于带辅助的街机驾驶样板，不是完整赛车模拟器。最终乐趣、声音音色和辅助力度仍需 Bobby 试玩判断。
- 长按约 0.8 秒手刹后直接重刹，曾出现 50.77° 的侧滑峰值；短按约 0.55 秒并反打的记录峰值为 14.85°，之后可恢复直行。长手刹仍容易过转，不能把成功收回的一次样本视为全输入保证。停车湾驶出记录中短暂出现三轮接地，制停时恢复四轮，需继续检查路缘反馈。
- HUD 氮气条和状态提示由主线通过以上接口集成；本分支只提供数据和操作说明。
- 实际展开设置菜单发现右栏自动最小高度超过弹窗，底部驾驶说明被裁切。已向主线交接 `.world-dialog-side` 的 `min-height: 0` 建议，`world.css` 归 UI 线，本分支没有改。操控文字存在不等于 UI 可读验收通过。
- offroad、van 还没有推广此套调校；没有增加赛道、地图或小游戏。
- 手柄映射已实现，尚需实体手柄验收；移动端仍沿用原有桌面体验提示。

4343 临时服务与自有 Chrome 试驾页已关闭，临时 public 链接与本机预览配置已移除，共享重型锁已释放。轻量日志和原始记录归本驾驶工作区所有，主线完成集成验证后可清理 `.astro` 内本轮临时资料。

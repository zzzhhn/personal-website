# 车辆上下车接触链与倾覆乘员修正

2026-10-27。起点 `d5224e3`，分支 `codex/world-alpha-pilot`。本轮源码和轻量骨骼检查已完成，浏览器体验与完整场景碰撞验收仍待主线程串行执行，未构建、提交或推送。

## 根因与改动

截图中的倒扣车仍有直立乘员，不是角色太高：`cabinAnchor` 已经用车辆完整四元数计算座位位置，但 `GuideVisual` 只传 `heading`，`WorldGuide` 又只设置 `rotation.y`。座位随车翻转，乘员的上方向和臀部偏移却仍按世界竖直计算。

现在实时传递车辆视觉原点与完整 `[x,y,z,w]` 四元数，包含 `bodyY` 偏移随刚体旋转后的结果。角色朝向在跨身期间过渡到车体坐标系，坐姿根位置和真实蒙皮臀部承托点也在同一坐标系求解。侧翻、俯仰、倒扣均保留可见乘员，没有增加倾覆隐藏规则。

原上下车时序先在门外执行 `SitDown`，之后才横移到座位。本轮改为以下窗口，共用暂停时冻结的物理时钟：

| 入车归一化进度 | 动作与接触 |
| --- | --- |
| 0～0.30 | 沿已检查的绕车路线走近。距离较长时按真实路径长度延长这段。 |
| 0.30～0.36 | 站立接近门的实际接触位置，手臂伸向门扇。 |
| 0.36～0.49 | 开门，手和身体跟随门扇外摆；蝴蝶门抬升时手掌向近铰链的推持点移动。 |
| 0.49～0.58 | 走到已经打开的门槛，先低头、屈身。 |
| 0.58～0.68 | 先抬起一只脚跨过门槛，骨盆仍留在车外。 |
| 0.68～0.80 | 重心跨入，另一只脚跟随；头部避让顶棚。 |
| 0.80～0.92 | 身体已经在车内后才播放源 `SitDown` 并对齐实际臀部承托点。 |
| 0.92～1 | 普通门在座椅前外缘前倾取内拉点，关门后回到座位中心；跑车按车内真实按钮电动关闭蝴蝶门。 |

固定标称时钟为 5.2 秒，实际进入总时长是按距离计算的靠近时间加 3.64 秒核心动作。下车逆向执行核心动作，到门外站定即可结束，不追加一段原地等待来倒放入车之前的远距离靠近。

普通门前倾阶段在车内前移 22 cm、向外移 18 cm 后回正，手部和上身约束共用时钟。跑车升起的蝴蝶门超出短臂角色从桶椅中的可达范围，因此采用主线程确认的电动关闭按钮；没有拉长骨骼。按钮模型与动画接触点共用 `vehicleDoorCloseContact`，两侧按钮位于真实内饰坐标，35 m 以外不绘制，没有新增灯光或计时服务。

动作使用既有 CMU 来源 Idle／Walk／SitDown／StandUp，加本轮编写的门扇接触、跨脚和上身避让约束。**这些新增约束是程序动画，不是新取得的车辆动捕。** 每帧在 mixer 更新之前恢复上一次约束，避免骨骼逐帧积累变形。

## 状态与安全边界

- 保留原蝴蝶门轴线、已生成门洞、座椅、驾驶碰撞体和回营地路径。
- 入车前仍检查停稳、外部绕行路线与 13 姿态门扇外摆。超过 30° 倾斜不启动普通门动作；已在车内的乘员继续真实随车倾覆。此时 E 提示按 R 扶正或回营地。
- 入车期间再按 E 仍排队退出。退出期间再按 E 不重置动作。
- 下车不再一开始就清空 `activeVehicle` 并启用场外 capsule。核心动作期间车辆保持刹停、玩家 capsule 保持禁用，站到门外后通过 `findSafePlayerLanding` 再检查落点、支撑与可离开路线，成功才恢复行走。
- 最终落点被新障碍占用时保留车内状态并显示原因，不强行把玩家放进障碍。该失败分支会恢复车内坐姿，其视觉连续性需要浏览器观察。
- 现有门扇检查仍是离散采样，没有增加门扇独立刚体，也没有完成全身连续的场景碰撞证明。

## 主线程浏览器复现场景

在现有可复用测试页启用 `?qa=1`，不需要本轮再开浏览器或服务。

1. 三车型各停稳，从前后两侧靠近后按 E。用慢速观察或已有 `holdVehicleTransition` 暂停在 `.35、.45、.63、.74、.85、.95`：依次确认手接触门、门打开、领先脚跨槛、身体跨入、车内落座、取拉点／按钮并关门；不能在远处形成完整坐姿再横移进车。
2. 正常驾驶后停车按 E，下车必须是先开门、车内起身、跨出、关门，然后恢复行走。按住 W 不得提前把仍在车内的 capsule 驱动出去；动作中再按 E 不得重置窗口。
3. 入座后使用既有 `worldActorDebug.flip('coupe')` 或页面公开的对应 debug 入口。看角色与车辆一同侧翻／倒扣，不能再保持世界竖直；读取 `actor().vehicleRotation` 与 `vehicle.frame.rotation`。按 E 应给出扶正／回营地提示。等恢复提示后按 R，角色回到正常座位，再正常下车。
4. 在墙边、窄缝、水边分别请求上下车；在退出过程中占据预定落点，观察拒绝与回座分支。测试回营地、暂停／继续、入车中排队下车以及重复进出后输入恢复。
5. 从车外侧面和低机位检查头、脚、衣物、手部与 A 柱／门槛／车门的实际穿插。特别观察普通门关门时的前倾与座椅边缘支撑、跑车按钮是否可见、蝴蝶门在按键接触前后的时序，以及退出最后一帧的转身连续性。

完整类型检查、构建、实际 Rapier 场景检查与用户视觉接受均未在本协作者执行。静态／骨骼通过不能替代上述实际体验验收。

## 2026-10-27 普通高门车型实机返修

主控在 offroad `q=.66` 复现躯干近水平，截图为 `docs/world/phase-2-playground/qa-20261027/offroad-threshold-before.png`。根因是三车型共用 `low=true`、`bendScale=1.3`，胸椎和上背合计约 82° 前屈；旧测试只限制头顶高度，没有限制头部下限或躯干倾角。

普通车现在在门外保持浅屈，领先脚先抬高再横跨，身体跨入时才加强避顶、屈膝和调整朝向；跑车保留原低门策略。车内使用既有 Idle／SitIdle 端点的车辆专用程序混合，避免源 SitDown 中段的深鞠躬。SitIdle 的缓存取其非循环 settle 末帧，与生产持坐和臀部测量一致。该层不参与营地／daybed 坐姿，不改变骨长、头部尺寸或人物比例。

生产座椅已经合并在 `G25_body`／`G27_body`，没有独立 seat 节点。运行时仅变换完整座椅局部三角形，L0／L1 共用合同：offroad 座垫顶 `.77→.63`，保留 `7.5 cm` 厚软垫，底面 `.555` 高于 floor `.55`；van 座垫前移 `.30 m`、顶 `.93→.835`，底面 `.795` 高于 floor `.79`。两车真实靠背后仰 30°，臀锚随真实座垫同步。van 后移会进入原有货箱隔壁，因此没有采用后移。没有改变整车高度、车壳、轮胎或悬挂，生产 GLB 与共享加载缓存不被改写。

脚底解算会改变臀／上腿蒙皮承托点，故普通车在脚约束后再收敛实际臀部接触，并重植双脚。普通门关闭使用实际内衬上的可达推持点；跑车电动按钮不变。全车四元数跟随与约束逐帧还原继续保留。

## 已有基础，继续沿用

主岛 V3/V4 和 Alpha 基础地形已使用构建生成的三角网格；回音洞与水车已有独立表面数据。大陆渡口、山路护栏、小屋、灯架等已有实物接触回归。小屋与灯架合计 247 个实体构件。当前图集对这两处、山路护栏和大陆渡口做严格的碰撞注册核对；其他区域也进入覆盖报告。模型与碰撞体同名只证明注册关系，形状、位置仍须用实际几何和物理查询校验。

已有共享 E 提示、短距自动就位和动作提交机制。洞口矿灯、矿山工具、货场与工厂控制已经修过具体的靠近与执行问题。渡船、雪橇、缆车和过山车已有跳过入口；旧符文桥已从实际场景移除。角色核心已经通过适配器接入多个场馆，部分步行、行车、乘坐及跳过路线也已检查区域就绪状态。Safari 曾有 HTTP 自动解压后的二次解压，以及 Alpha 上车遮罩容量不足两种独立启动故障，保留这两项回归。

## 剩余工作与优先级

1. **P0，全图接地与碰撞来源。** 盘点主岛、山岛和独立设施的实际可见网格、支撑表面、摆放调用和碰撞体。松树树干仍使用单独定义的碰撞盒，是可直接调查的候选。以玩家可遇到的风险决定批次。让渲染、物理、落脚和救援使用同源几何及变换；保留洞顶、洞底、桥面等多层表面的身份与查询起点。全图扫描要能检出悬空边角、埋入、门槛断层、堵住的空隙和空气墙。每个可见模型或合并模型的每一段都要明确归为 `solid / pushable / soft / none`，实例与 LOD 也要覆盖。固体和可推动物需追溯到实际形状、姿态和实例。逐区域扩大强制范围，最终让遗漏分类直接导致构建失败。禁止用统一补 `none` 的方式消除缺口。
2. **P1，核完全部 E 动作。** 从实际注册表枚举动作和入口，记录展示条件、站位、负责人、成功后的状态变化、取消与重试。确保玩家看到的目标就是按下后执行的目标。条件稳定时，一次输入可安全走近并恰好提交一次；目标移动、通道变堵或玩家主动改向时，应给出明确反馈并交还控制。覆盖键盘、手柄和已有面板入口。用洞口矿灯、两张货场工作台、工厂控制、渡口和四类乘具做端到端回归，同时检查尚未迁移的动作。
3. **P1，收口角色核心与区域就绪边界。** 核对角色输入、移动、载具、镜头、交互注册表和共享 store 的剩余职责与依赖。场馆自己持有状态、碰撞就绪条件和行为，核心只消费通用契约。沿真实入口逐区验证初次出生、徒步跨界、开车、上下车、跳过到站和救援回落。用延迟加载、卸载、重挂和加载失败制造边界条件，验证安全等待、恢复和可操作的错误反馈。
4. **P1，补完行为测试与昼夜验收。** 盘点仍读取源码字符串、旧提交或 AST 的测试。先用真实组件、Rapier 或渲染结果覆盖它防的故障，再替换脆弱断言；保留有独立价值的依赖边界检查。继续使用 21 个固定机位的昼夜图集；新暴露的地形接缝需要时才补机位。交付同机位、同画质、同曝光的前后证据及 commit、manifest 和 CI 链接。漏标、空帧、资源加载失败或缺机位均须在相应检查里清楚报出。
5. **目标机验收贯穿上述批次。** 已有 16 GB M3 Air、Safari 26.5 的历史营地样本：冷 HTTP 缓存到可操作 10.67 秒，随后约 14 秒路线平均 16.99 FPS。它只代表当时那个版本和路线。复测普通 Balanced 入口、营地、Alpha 和一个重场馆，记录机型、分辨率、缓存、到可操作时间及帧时间分布；另外记录拾取手感与洞口、坡面、门槛的实际画面。如果工作电脑不是目标机，先完成其余证据，给 Bobby 一条简短的目标机复测路线，明确标出待验事项。

## 怎么交付

每批回答三个问题：哪条普通玩家路线会出错，修复前有什么可复现证据，修复后同一入口发生了什么。根据改动运行针对性行为测试、`npm run check:grounding`、必要的 `npm run check:coaster-scene`、`./node_modules/.bin/tsc --noEmit` 和 `npm run build`。把提交、覆盖变化、实测及余项写回迁移台账。最后按五项目标逐项给出通过证据、剩余例外及需要 Bobby 体验的具体位置。只有各项验收成立才标记整项目标完成。

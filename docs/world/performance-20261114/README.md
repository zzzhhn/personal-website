# 转镜头/移动/跨区域性能专项

基线facdc92（factory runtime4fb09e4），不改变DPR、纹理、近远模型、光照/阴影精度、物理或玩法。当前在独立world-performance工作树，4341保持已交付基线，候选4364。

## 原因与测量

首轮profile定位Three WebGLProgram首次使用和map静态路径字符串。截图API产生约1秒人为停顿，已在r2起独立标capture相位，不能算进交互卡顿收益。

- r2: 首次绕视最大716.6ms，超过250ms六帧；第二次绕视49.9ms以内。未证明所有转向持续秒卡。
- 夜间基线：进入工厂灯总数22→24，离开24→22；Club/街灯visibility还会改变参与灯数。首次进入37次新program链接，首次离开20次。对应进入最大183ms、离开最大2133ms；同期系统缓存/编译负载会波动，需候选同路线重复核验。
- CPU采样约3.2秒花在WorldMap静态path map/join，字段每10Hz位置更新重复计算。优化只缓存显式不可变数组，动态坐标/marker不缓存，44个真实数组输出相同。

## 变更候选

1. 小地图不可变路径字符串缓存（WeakMap/显式注册）。局部微基准不外推成FPS。
2. Club、街灯、工厂保留固定灯槽，仅将原不参与灯的intensity置0；位置/有效时强度不变，避免光源数量导致材质组合变化。会增加零强度灯参与的着色器计算，实际稳态耗时必须检查。
3. 遮挡淡化副本缓存由独立作者实现，生命周期测试与浏览器验证后再合入，不以源码推断当收益。

原始探针有GL调用计时/CPU profiler时标注诊断；正式确认应关闭CPU profiler、保持相同画质/路线并复跑基线与候选。后续内容建议在NEXT-CONTENT.md，只是讨论稿。

## 被拒绝的预热候选

a88d4bb中的全场景compileAsync预热在confirm-b1首次绕视出现9.88秒，虽然跨区稳定，但启动体验不合格。不能用后续顺滑掩盖这一退步。改为只对相机60米内几何、每个任务最多一个mesh异步提交；按材质身份/版本缓存，不改变ready门、任何可见几何或画质。最终确认需要重建这个版本后另行测量。

## 最终候选46e6e81的复核边界

四份无CPU采样器、无GL封装、无截图计时窗口对照见comparison.json。A1/A2基线来自先前BAAB；受限预热的最终B1/B2在其后连续跑，不伪称冷GPU缓存随机试验。其它用户应用未关闭，系统内存/外部负载未控制。

- 首次进工厂：A1/A2最大3733.2/166.7ms，B1/B2均16.8ms；第一次离厂1633.2/133.3ms→16.8/33.3ms。同一真实W/鼠标路线抵达坐标一致。固定灯槽解除进出时的程序重新组合，源机制与带GL链接计数的前期诊断互相支持。
- 第二轮营地绕视：最大50.1/33.4ms→16.8/33.4ms，均不是冷编译；不当作巨大FPS收益。
- 首次绕视仍有卡顿：最大1233.3/616.6ms→1116.6/733.2ms；>50ms帧22/22→14/15，>250ms仍5帧。改善有限且有波动，不能写“首次转向已解决”。
- 营地移动没有稳定收益：候选一轮p95 33.3ms，另一轮16.7ms。不得挑好的一轮掩盖。大多数阶段帧率受60Hz封顶，平均FPS不用于宣称收益。
- 遮挡缓存的8个生命周期case通过，老实现7个失败。实测路线未产生遮挡cache hit，故不把它作为本路线性能收益归因；真实遮挡画面和缓存用途须由单独视觉窗口检验。
- 所有模型/纹理/public资产及画质/阴影/物理源264个文件保持逐字节一致，新增的是缓存/编译安排和零亮度灯槽，不降画质。

真实遮挡补验：fade-runtime在原营地树/帐篷附近真实鼠标低机位两轮绕视，创建17份副本、复用17次，0pageerror；已查看实际透明画面。该补验仅证明复用/画面，未给出独立帧耗收益百分比。

# Phase 2：把个人世界做成值得探索的 playground

2026-10-25：Bobby 已授权启动人物动作、驾驶和美术开发；地图和小游戏本轮只做方案。以新版与当前动作修复为基线，初期交接方案作为背景，技术路径和具体玩法保留探索空间。

## 第一段完整体验

先做一段几分钟就能感受到变化的路线：从营地出发，走跑和翻越障碍，靠近车辆并上车，沿海岸驾驶，在一处项目装置下车体验，再自由离开。人物、驾驶、地图和美术都在这段路线内产生可见成果，然后扩展到全岛。

完成的判断首先是连续玩起来是否自然、有趣、让人想再玩一次。项目与经历自然融入世界，不能把游玩变成工作演示、培训或评测任务。访客也应能够快速找到项目和经历，不必被迫通关。

## 四条工作线与可直接使用的 prompts

### 1．角色动作与行为链

先完善起步、停止、变速、转身、跳跃落地，以及坐下和起身的衔接；再补上下车与低栏翻越。检查原有动作来源，比较许可明确的真人动捕素材，关注重心、身体预备动作、手脚接触和操作响应。动作质量由游戏里的最终表现判断。

> 继续改善这个世界里人物的动作和行为，让他走跑、转身、跳跃、坐下时更像一个有重量的人。可以研究和使用合适的真人动捕，重点把连续动作做自然，再补上可信的上下车和翻越低栏。请自主选择实现方法，先给我一段能直接试玩、看得出区别的完整体验。

### 2．驾驶物理与驾驶乐趣

先做一辆明显好开的标杆车，建立车重、轮胎抓地、转向、刹车和悬挂的可信反馈，再加入可控漂移、手刹与有限氮气。音效、镜头与轮胎反馈共同表达状态；以容易上手、有练习空间为方向。随后再区分其他车型。

> 把现有驾驶做得更有重量、更可信，也更好玩。先把一辆车的加速、转向、刹车和路面反馈打磨好，再加入可控漂移和氮气加速。希望新手能开起来，熟悉后又有技巧可练。具体物理和实现方式你来判断，用一段好玩的试驾路线展示结果。

### 3．地图与可玩的个人经历

先从玩家想做的事出发，设计场所、动作、即时反馈、探索惊喜和重复游玩的理由，再自然连接项目。当前只提出方案，保留 Bobby 后续补充空间，不实现地图或小游戏，也不把候选变成冻结方案。

> 为这座岛设计真正让人想玩的地方。先想玩家会做什么、有什么惊喜、为什么想再玩，再自然联系我的项目。以露天 Club 和可以亲手开采的因子矿脉为灵感，给我一些有空间感、有动作、有乐趣的方案；这轮先不开发，给我留出继续补充的空间。

用户提出的具体方向，属于待设计玩法，不代表现成功能：

- **DJC × 合拍露天 Club**：真实搭建可进入的 Club，包含舞池、Disco Ball、灯光等空间元素，让角色能够蹦迪。音乐系统服务于游玩的现场感；不把它缩成网页混音工作台。
- **Alpha Agent 因子矿脉**：把“挖因子”变成双关玩法。玩家拿着镐子和因子探测装置，在立体矿脉中搜寻、辨认和开采，再把挖出的因子投入“回测池”查看真实结果。方案需要说明实体玩法如何映射因子，以及真实回测需要什么数据／服务；展示结果时保留数据来源和时间范围，不用随机数字冒充实际结果。
- 其他项目继续发散。先前的评审影院、研究站等提法未获 Bobby 认可，不作为默认实施方向。避免每个区域最终都变成操作面板或工作流程换皮。

Club 与矿脉可以有不同节奏：前者适合停留、表演和自我表达，后者适合探索、发现和尝试。设计 session 可提出进一步创意，不擅自锁定完整机制、奖励经济或地图规模。

### 4．美术、材质、光影与 UI/UX

先检查建模比例，尤其是用户指出的传送门：目前明显偏椭圆，模型本体应更接近规整圆形，并分别检查模型比例、实例缩放和正常镜头下的投影，不能通过扭曲模型补偿某个机位。再选择代表场景改善材质尺度、粗糙度、接触阴影、植被层次与信息层级。生成图片可用于概念对比和纹理探索，最终以游戏中的实际效果评判。

> 保留新版世界的气质，改善建模、材质、光影和 UI。先把明显偏椭圆的传送门修成更规整的圆形，再挑几处代表场景做有审美判断的优化。关注自然感、细节和交互可读性，也兼顾流畅度；请直接做出可试玩的改进。

## Sessions 与协作

- 一个主 session 负责整体方向、试玩反馈和集成；四条工作线可以拆 session，各自按需使用 subagents。
- 第一轮：动作、驾驶与美术样板可以并行；地图线先进行创意和路线设计。
- 第二轮：合成上述完整路线，重点检查上下车、翻越和装置交互之间的衔接。
- 第三轮：根据实际试玩反馈扩大地图、增加装置、推广样板质量。
- 每条线保持独立分支，共享角色／车辆／输入接口的改动先协调，避免多个 session 同时重写同一控制器。每轮交付小而完整的可试玩结果，并说明哪些是候选、哪些仍有问题。

通用开场白可以保持很短：

> 以当前新版代码和最新修复为准，先了解已有成果。这里给的是体验目标，具体方案可以自主判断；请尽早给我一个能玩的版本，我们再通过实际体验继续调整。

四个 session 必须从协调 session 同步到 GitHub 的同一提交起步；分工与运行资源安排见 [协作说明](phase-2-coordination.md)，已有技术验证与残余问题见 [修复记录](local-motion-fixes-20261025.md)。

动作研究可参考 [Epic 官方 Motion Matching 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/motion-matching-in-unreal-engine) 中依据姿态与运动轨迹选取动作的思路；执行阶段再判断对现有 Web 项目的适用性与成本，不在此草案中锁定算法或引擎。
